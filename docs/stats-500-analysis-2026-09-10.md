# 余记：五年 500 条数据验收与统计下钻设计

日期：2026-09-10。对象：原生 iOS 余记，模拟器优先。所有数据都是确定性生成的样例，使用独立文件；不导入个人账本。

## 用户真正想回答的问题

统计应围绕一条完整动线：**看总量 → 找构成 → 解释变化 → 核对具体记录 → 必要时编辑 → 返回原来的分析上下文**。

| 用户问题 | 默认展示 | 点击之后 | 防止误读 |
|---|---|---|---|
| 这个月花了多少、还剩多少？ | 净支出大数字，支出和退款拆开，收入与结余 | 切月、切年，直接选年份月份 | 转账、期初、草稿、回收站不算收支 |
| 钱主要花在哪？ | 一级分类支出环形图 + 金额排行 | 图上选择查看占比；排行直接进入该一级分类 | 环形图只画非负支出，不以净支出作为分母 |
| 是次数多，还是单次金额大？ | 分类金额和支出笔数；可改按笔数排行 | 二级分类 → 流水按金额排序 | 退款不算消费笔数，但退款流水可查看 |
| 为什么比上期多/少？ | 同环比变化卡 | 明确本期/基期日期、两期金额、分类变化贡献 | 比较净支出，减少不能直接推断节省或消费习惯改善 |
| 哪几笔导致变化？ | 分类变化按绝对金额排序 | 分别打开本期、基期分类或全部流水 | 贡献金额有正负，各分类变化合计等于总变化 |
| 查几年前的一笔、退款是哪年的？ | 年/月直达，流水显示完整日期 | 二级分类 → 明细 → 原消费/退款 | 关联退款也显示年份，避免同月同日混淆 |
| 看完明细怎么回去？ | 原生返回 | 保留原日期、分类、图选择、排序 | 编辑后重新计算金额，不保留旧统计快照 |

研判：默认先给一级分类，符合先整体后局部的分析方式。二级分类只在用户选择一级后出现，避免首页罗列几十个叶子分类。图与排行是同一组数据的两种展示，不引入第二套分类、标签或筛选规则。备注只存上下文，不进入筛选。

## 统计契约

- 单位统一使用整数分。支出 E、退款 R、净支出 N=E−R、收入 I、结余 S=I−N。
- 退款按实际退款日计入期间，分类跟随原支出；跨年退款不回改原年支出。
- 分类图分母为该期间毛支出（收入模式为收入总额）。退款类只有退款、没有新支出时不画虚假占比，保留退款分类与明细入口。
- 分类行的「笔数」只统计支出/收入本身；明细「条流水」包含该期间退款，所以两者可能不同，界面分别标识。
- 每条支出或收入只有一个二级分类。一级合计=其全部二级合计；退款归属相同树。归档分类仍进入历史分析。
- 当月：1 日至今天；环比为上月相同进度，同比为去年同月相同进度。历史月：自然整月对整月。
- 基期月份不足共同天数（如 3/31 对 2 月）时，金额只比较共同天数，不给增长率；主总额仍按当前选定期间统计。比较详情列出两组精确日期。
- 当前年：1/1 至今天，对去年相同月日；2/29 年度比较使用共同 1/1–2/28，而年度主总额仍包含 2/29。历史年比较两个完整自然年。
- 基期为零、为负、早于账户记账起点时不计算增长率。记账起点只是可记录范围的下界，不能证明用户没有漏记。未覆盖基期不生成“增长了多少”的结论。
- 比例按正基期计算，可能小于 −100%（本期净支出为负）。这表示退款影响后的净额变化，不代表消费减少超过全部消费。
- 排行主次规则：金额/笔数/退款降序，平局按稳定分类 ID；切换排序不改变图的分类顺序和颜色。流水支持时间降序与金额降序，返回保留选择。
- 历史数据可以有空月份；空月展示 0 和明确空状态，不自动补成消费或收入。

## 数据集与独立核验

生成器：`scripts/generate-stats-fixture.mjs`。固定随机种子 93741。原始快照：`Fixtures/stats-500.json`；独立答案：`Fixtures/stats-500-oracle.json`。

共 **500 条持久化交易**：360 支出、80 收入、30 转账、30 退款。其中 20 条支出在回收站、10 条有效交易属于隔离对照账本；主测试账本有 **470 条有效流水**。另含一条未保存草稿，不算交易。覆盖 **2022-01-01 至 2026-09-10**，共 57 个自然月、5 个日历年（约 4 年 8 个月）。

专门覆盖：2022-12-31 消费与 2023-01-15 全额退款；2023 年 1 月仅退款、2–3 月为空；2024-02-29 闰日；跨月部分退款；不同到账账户；归档娱乐分类；长备注；零钱与大额；回收站、转账、期初余额、另账本和草稿隔离。

主账本全期独立答案：

| 退款 | ¥19,241.12 |

## 本次发现与处理

| 优先级 | 旧行为 / 风险 | 本次处理 |
|---|---|---|
| P1 | 大额编辑、退款和期初余额预填复用千分位展示字符串，导致计算器无法解析或金额误读 | 单独提供无分组、无区域歧义的输入格式；旧表达式无效或与金额不一致时以整数分回填 |
| P1 | 收入分类计算无条件混入支出退款，出现负的消费分类 | 只有支出分析归集退款，收入保持互斥 |
| P1 | 声明了基期未覆盖状态，但从未判断，容易把未记账当作 0 | 依据账户记账起点判断；未覆盖时不生成增长结论 |
| P1 | 负净支出趋势柱被压成 0，退款月份失真 | 原生图表保留零轴上下的有符号数据，点月可核查 |
| P1 | 以净额做占比分母，负分类被隐藏、正分类可能超过 100% | 分布改为毛支出/收入，退款另列，净额用于总览和变化 |
| P2 | 只有叶子分类静态列表，无法核对分类金额来源 | 一级图与排行 → 二级 → 逐笔流水 → 可编辑详情 |
| P2 | 只有前后月按钮，查五年前要点几十次 | 年/月选择器直接跳转，支持回到本月 |
| P2 | 流水与退款关联只写月日，五年记录易混淆 | 流水和退款关联使用完整年月日 |
| P2 | 排行相同金额顺序不稳定 | 统一稳定排序；支持按金额/笔数/退款查看 |
| P2 | 筛选后不知道当前条件，空结果难恢复 | 流水显示活动筛选摘要和清除入口；重开筛选带回原条件，键盘搜索可直接应用 |
| P2 | 年图最后月份标签接近边界、零线重复绘制 | 为横轴留边距，零线只绘制一次 |

## 验收与交付记录

核心验收：70 项 Swift 测试通过，其中新增 9 项覆盖 500 条样本、57 个月/5 年、收支分类、父子与下钻守恒、备份/编辑/恢复、比较边界、重复查询和金额编辑格式。

本机测量：连续执行 500 组「年度汇总 + 分类分组 + 下钻查询」耗时约 1.28 秒。此数为本机领域层测试，不是 iPhone 帧率、冷启动耗时或长期运行证明。

原生 UI 验收：iPhone 17 Pro 通过 9 项（5 项统计流程 + 4 项既有分类入口回归）。iPhone SE 小屏通过 6 项：相同 5 项统计流程，加 1 项流水搜索/筛选恢复，包含最大辅助字号与深色模式；最终日志 `evidence/stats-500/ui-verified.log`，原生结果 `ui-verified.xcresult`；流水筛选为 `ui-feed.log` / `ui-feed.xcresult`。截图画廊为 `evidence/stats-500/index.html`。

验收中发现最大辅助字号下日期拆行、金额挤压，已改为纵向布局、完整日期、文字排行。小屏首次年度入口失败是测试的大幅滑动跨过单行目标，录屏显示页面已滑到列表底部；将测试手势改为短距离且可反向调整后重验，不作为 App 缺陷计数。

## 后续优先级

已实现的动线用于验证个人分析的完整闭环。以下保留为后续增量，避免当前统计首页变成密集仪表盘：

1. **自定义日期 / 多期间对照**：当用户明确需要旅行周期、工资到账周期分析时加入；同期规则仍要清楚展示。
2. **分类预算与累计曲线**：只有用户先设预算才讨论剩余额度和进度，不把支出增长自动解释为不好。
3. **笔均与高频驱动分解**：结合笔数变化与单笔金额变化，区分频率、单价与退款；避免用一条异常大额给出生活方式结论。
4. **多账户钻取与对账**：在既有期间/分类内切换账户，必须继续区分现金流账户与原消费分类；暂不引入服务端。
5. **多分类分布**：一级分类超过 8 项时考虑尾部合并“其他”并保留下钻，当前实现逐项展示，不能把几十分之一百分点的小扇区当作唯一点击入口。
6. **更多数据与设备**：500 条可验证五年交互及正确性；1 万条以上性能、真机功耗/帧率、iOS 16 最低版本运行仍需另验。

## 设计依据

Apple 的图表设计指导强调先给概览，再通过交互查看细节，并为图形提供可读信息与可访问入口。本次采用“总览—构成—变化—明细”的渐进披露，图形之外保留排行、月份按钮与金额文字。[Apple HIG Charts](https://developer.apple.com/design/human-interface-guidelines/charts)、[Design app experiences with charts](https://developer.apple.com/videos/play/wwdc2022/110342/)。

环形图选择展示某分类，排行可直接下钻；月柱选择进入对应月份。iOS 16 保留自绘环形图与 Swift Charts 柱图，不提高最低部署版本。[Apple ChartProxy](https://developer.apple.com/documentation/charts/chartproxy)、[Beyond the basics of Swift Charts](https://developer.apple.com/videos/play/wwdc2023/10037/)。

## 本地体验

执行 `./scripts/run-stats-stress.sh`，会构建并在 Yuji-Acceptance 模拟器打开独立样例，定位 2025 年，可切换月度与年度统计。脚本每次使用新 UUID 文件，支持自由修改样例。退出样例：终止 App 后，以不带 `YUJI_STRESS_SESSION` 的普通方式启动 App，恢复原来的个人数据文件。测试入口仅在 Debug 下存在。

最终交付核对：`evidence/stats-500/verification.json` 记录 70 项核心测试、iPhone 17 Pro 9 项原生流程、iPhone SE 5 项统计 + 1 项流水流程、34 张原生截图。安装/启动独立样例前后，正常个人账本 SHA-256 一致；模拟器重新安装时容器路径可能变化，比较的是文件内容哈希。可用 `node scripts/verify-stats-delivery.mjs` 重新核验交付文件与日志。
