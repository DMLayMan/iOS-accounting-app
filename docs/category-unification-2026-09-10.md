# 余记：统一二级分类与快捷录入

2026-09-10 · 产品决策、调研、实现与验收记录。本文取代前一轮“分类 + 标签”作为日常录入概念的设计。

## 1. 已确认的产品规则

用户确认：一笔账一个二级分类；备注只承载用户信息，不参与筛选；优先优化分类展示和 CRUD。

因此，日常操作只保留一套分类树：一级组织，二级记账。例如“餐饮 → 咖啡茶饮”。同一笔钱在分类统计中只归属一个叶子，一级汇总其下级。备注可写“和朋友喝咖啡”，但不生成另一个可筛选维度。

原先分类回答支出类型、标签回答项目/对象等交叉维度，两者确实不同；然而本产品没有明确的跨维度分析需求。研判：继续保留两个高频入口，会让用户为未使用的分析能力付出录入和管理成本。技术上可以统一，产品上也应按当前目标统一。

取舍：不再支持新增按“朋友/出差”等备注内容筛选；也不通过把不同维度拼成大量“出差咖啡/朋友咖啡”分类来变相恢复标签。只有用户经常需要独立统计时，才自行新建有意义的二级分类。

## 3. 展示与操作动线

### 录入页

- 只显示一个分类区，首屏六项，三列两行；按钮最小高度 48 点。
- 直接点击二级分类即选中，显示完整一级/二级路径。不要求先点击一级。
- 最多置顶四项，按置顶先后占据固定位置；其余位置按本地习惯推荐。
- 本次录入的推荐 ID 列表只在打开时建立；输入金额、备注、选择分类不会重新排序。主动置顶/取消置顶可刷新，切换收入/支出重新取得各自推荐。
- 选中常用区外的分类时，显示完整路径，不把它强塞到首位导致其他项移动。
- 金额键盘与文字输入状态互斥。没有标签输入、标签推荐或标签选择步骤。

### 全部分类

- 一级分组组织二级列表；直接点选二级后返回记账，无额外完成按钮。
- 搜索一级名称可找到其全部下级，搜索二级名称保留父级上下文。
- 现场新建二级分类，填写名称并明确选择父级；管理模式中的“新增二级分类”会预填当前父级。
- 目录管理放在独立模式；普通选择页不常驻归档/删除操作。

### 分类 CRUD

| 动作 | 本轮规则 |
| --- | --- |
| 新增一级 | 名称必填；同账本同收支类型的一级不重名 |
| 新增二级 | 必须属于可用一级；同父级不重名；不同父级允许同名并展示完整路径 |
| 查找 | 支持父级/叶子名称搜索、按分组浏览；管理可显示归档项 |
| 改名 | 去首尾空白、拒绝重名；ID、金额及历史引用保持不变 |
| 调整所属分组 | 仅限同账本、同收支类型的一级；不能形成三级/环；表单明确提示历史汇总也将跟随新分组 |
| 置顶 | 最多四个可用二级分类；本地保存，备份可恢复；取消置顶后回到推荐排序 |
| 归档/恢复 | 归档不删除记录，停止新记录选择与推荐，取消置顶；一级动作连同下级执行，界面明示影响 |
| 删除 | 只允许没有交易（含回收站）与草稿引用的分类；一级必须连同下级都未引用，检查通过后整体删除，避免半删除和孤儿节点 |

未提供“智能自动归类”或默认悄悄选第一项。推荐只是候选展示，账单最终分类由用户明确选择。

## 4. 本地推荐模型

实现位置：`Sources/YujiCore/CategoryExperience.swift`。

候选集：当前账本、当前收入/支出类型、可用的二级分类与可用父级。只使用有效账单；退款、转账、草稿、已删除记录不增加偏好权重。按账单发生日期计算，不用修改备注时变化的更新时间。

当前启发式：最近 90 天内，按“每天该分类使用次数（每天最多计 3 次） × 0.5^(距今天数 / 14)”求和。先放置顶项，再按得分排序；同分用既定顺序与稳定 ID 打破平局。无历史时沿用默认目录顺序。

这些窗口、衰减与上限是初始产品参数，不是统计验证后的最优值。当前无导入来源字段，无法完全区分导入历史与日常录入；每日上限只降低单日大量记录的影响。后续支持批量导入时应补充来源信号。

备注、金额、位置、通讯录都不参与模型；不调用模型 API 或自建服务器。没有发生时刻字段时，不把录入时间伪装成早餐/午餐发生时间。本轮先不做时段预测。

## 5. 搜索、统计与历史兼容

- 流水关键词仅匹配分类路径，不匹配备注；支持一级或二级分类筛选。退款沿原支出的分类匹配。
- 统计移除“标签支出”，仅保留分类维度；原有按二级分类汇总与金额口径继续使用。
- 旧标签字段和 ID 保留在数据与备份中。编辑旧账单时原附加信息保持；详情称为“历史附加信息”，不再暴露新增标签入口。不将旧标签复制成分类或拼接到备注。
- `CategoryNode.pinnedOrder` 为可选字段；旧文件缺少该字段可直接解码。未执行破坏性迁移，也未修改历史金额。

## 6. 验收与下一步

已完成：原生实现、58 项测试通过、最终模拟器构建成功。新增 9 项测试涵盖旧分类解码、CRUD/草稿与历史关联、删除原子性、推荐频次与隔离、置顶限制与恢复、备注排除、父级搜索。日志位于 `evidence/category-unification/`。

已原生操作：打开新版录入、六项展示、一级与二级搜索、选择常用区外分类并返回、进入新增二级表单。改版后仍正确读取原模拟器账本，净支出 110 元、收入 500 元。进一步已实际保存 18 元测试账：一个二级分类、零个标签、备注完整保留；重新读取模拟器文件确认旧账单金额、备注和标签引用保持。证据见 `evidence/category-unification/ui-verification.json`。更多视觉证据以截图页的实际标注为准。

验收限制：当前 UI 控制工具的坐标操作返回 `noWindowsAvailable`，部分原生导航栏按钮没有暴露可点击元素；管理模式内完整保存、置顶、归档、删除的 UI 闭环尚未全部验证，领域规则已有测试。不能将测试通过等同于全部 UI 验收。真机、VoiceOver、最大动态字号仍待验收。

产品效果目标（待实测，不是已达到的结果）：积累至少 30 笔后，前六项命中率目标 ≥80%；常用分类选择 1 次点击；全部分类选择通常 2–3 次动作；相比旧版同一批录入任务，分类选择时间中位数下降 ≥30%，误选率不升高。用自有设备的小样本对比评估，不加入线上埋点 SDK。

后续按证据排序：P0 完整真机管理验收；P1 长名称与动态字号、置顶拖动排序与推荐效果评估；P2 用户确认后再考虑分类合并、整笔常用模板。以上后续能力均未标为本轮已实现。
