# 余记 · 全页面设计改造与原生验收

2026-09-10。范围：iPhone 原生应用；保留已确认的二级分类、长按排序与本地存储规则。本次在已有未提交工作上增量修改，没有提交、推送或发布。

## 用户最关心的两条动线

**创建分类：** 记账页的“新增” → 70% sheet → 填名称、选图标 → 创建并立即选中。图标预览、一级归属与图标网格在同一表单；28 个离线 SF Symbols，不再另开图标页面。输入名称时可展开以容纳键盘；无障碍大字号使用展开后的纵向布局。改名、调整归属、切换图标使用一次持久化操作，失败保持输入；旧分类没有图标字段也能正常读取。

**统计分析：** 饼图或排行 → 下方二级筛选 → 汇总和流水即时联动，始终停留在统计页。一级排行默认前四项，可展开；排序与清除筛选靠近明细标题。只有打开单笔流水才进入详情，返回保留分类、日期与排序。同比、环比在页内选择本期/基期，同步图表和流水范围；没有“看明细”七分屏。

饼图分母按当前区间的毛支出或收入，选择分类不改变总分母；退款单列，流水汇总展示净支出。500 条固定数据覆盖 2022-01-01 至 2026-09-10；9 月餐饮 ¥501.05，选咖啡茶饮后 2 条、¥139.90，清除后恢复总额。这些数字由原生测试断言。

## 全页面审查及实际优化

先完成独立的体验审查和原生技术审查，再合并优先级；改动后做有界复核与原生截图确认。不是把 CSS 检测结果用于 SwiftUI。详见 [Assessment A](design-review-assessment-a.md)、[Assessment B](design-review-assessment-b.md)、[源码复核](design-review-followup.md)。原报告分数是修改前快照，不作为本次完成后的评分。

| 页面族 | 本次落地 |
|---|---|
| 首页与四个 Tab | 首页统计入口切换同一个统计 Tab；记账动作只占根页面安全区，详情和设置不再覆盖按钮；最近记录补日期与分类图标 |
| 记账、编辑、退出 | 保留金额/文字键盘互斥与新建草稿；旧账编辑采用页内继续/放弃；账户、日期、分类工具扩大触点；大字号分类改可读的纵向选择 |
| 新建/编辑/全部分类 | 新增七分屏图标表单；同一图标用于录入条、目录与流水；大字号目录改一列；选中态提供勾选和辅助功能语义 |
| 月/年统计、比较、分类、流水 | 移除下钻 sheet；图表、一级、二级、日期口径与明细共享选择；压缩图表与流水之间的重复信息；整条排行可点击 |
| 流水、搜索与单笔详情 | 保持分类搜索语义，备注不参与筛选；详情大字号换行；统计内编辑/退款后刷新，返回保留上下文 |
| 退款、转账 | 统一任务 sheet 和修改退出保护；退款超过可退额度就地说明；失败不关闭表单 |
| 账户、账本切换 | 期初金额完整校验，非法文字不默认为零；错误留在表单；保存、归档、切换只有成功才退出 |
| 我的、账户/账本管理、最近删除 | 使用系统语义字号与深浅色 tint；保留原生分组结构；子页面不再被记账按钮抢占空间 |
| 备份、恢复与导出 | 导入先预览范围，再确认替换；替换前保存独立恢复点，主库成功保存时才切换指针；文件生成失败有反馈；“最近生成”不等于已保存到外部 |
| 外观与反馈 | 深色实心按钮使用可辨认的前景；触觉开关接入原生分类条；减弱动态同时尊重系统与 App 设置 |

源码审查覆盖当前可达页面和入口；现场验收覆盖证据页列出的页面、状态及主要路径。没有把历史标签页、未进入的系统文件目的地或所有错误组合算作已运行验收。

## 复核发现的关闭状态

- **F1 恢复失败消耗旧恢复点：** 改为 UUID 不可变文件与主库内指针。故障测试令主目录不可写、恢复子目录仍可写，确认新快照已生成但主库保存失败；当前主库字节、内存账本、旧恢复点指针与文件全部保持。
- **F2 超额退款没有禁用原因：** 提示由当前输入直接计算，不依赖已经禁用的保存按钮。
- **F3 收入被读作净支出：** 收入辅助功能汇总只包含收入、笔数和日期；完整 VoiceOver 朗读仍待实际验证。
- **小屏最大字号布局：** 分类归属和图标操作改上下排列；录入固定键盘上方不再放大段草稿说明；统计排序采用自适应布局。
- **SE 最大字号筛选卡顿：** 最终布局批次在切换二级分类时出现主线程持续忙碌；运行采样指向 SwiftUI 的 LazySubviewPlacements/布局更新。将内层明细改为普通 VStack，保留外层懒加载与首批 20 条/按需更多，避免嵌套懒布局互相失效；增加父级/二级反复切换的原生回归。采样保存在 `evidence/design-quality/compact-layout-hang.sample.txt`，最终稳定性批次单独留证。

## 验证结果

原生日志、xcresult 与截图位于 [evidence/design-quality](../evidence/design-quality/)，[验收页](../evidence/design-quality/index.html)收录 106 张原生截图，可按设备/页面族切换，来源逐张记录于 `screenshots.json`。

| 批次 | 结果 | 证据 |

| 管理页面、分类和大字号 · SE | 8/8 通过 | `compact-confirm.log` / 同名 xcresult |

| 卡顿修复后 · Pro | 3/3 通过：同页筛选、最大字号反复切换、年统计/收入 | `pro-stability.log` / 同名 xcresult |
| 卡顿修复后 · SE | 2/2 通过：同页筛选、最大字号反复切换 | `compact-stability.log` / 同名 xcresult |

上述原生测试去重后为 19 条 UI 场景，跨页面巡检用例内包含多个页面。最后一次构建 `build-stability.log` 为 TEST BUILD SUCCEEDED。没有把每个设备都跑过全部 19 条作为结论。

- `swift test`：75 项通过，覆盖分类图标兼容/备份、500 条统计及同环比、AppState 失败回滚、真实文件与恢复点故障。
- 所有 UI 测试使用新 UUID 的隔离账本；不重置用户已使用的体验账本。
- 验收结束已重新启动用户原有的体验 session；个人 `ledger.json` 的 SHA-256 与改动前一致，见 `data-protection.json`。没有执行重新播种或清空账本。
- 早期失败日志保留用于追溯：包括真正的整行点击区域问题，以及 XCTest 对被安全区遮挡/未滚入屏幕控件仍报 hittable 的定位问题。后者通过可见区域判断与显式返回顶部修正，不把修正前失败批次包装成通过。

## 边界与后续待办

- 本轮为 Simulator 验收，iPhone 17 Pro 与 iPhone SE 3，iOS 26.5；未在真机测试触觉、VoiceOver 全程操作，也未遍历所有 iOS 16–26 版本。iCloud 与签名发布不在本轮范围。
- 500 条数据校验不等于 5 万条数据性能验收；全量 JSON 保存仍在主线程，大规模数据应先 profile 再调整。
- 空账本/无账户的一步创建引导、归档账本的只读呈现、错误退款的撤销路径仍列为下一批产品工作；本轮没有凭空改变这些数据规则。新增账单保存后回到账本 Tab 保留现有行为。
- 系统文件导入的完整外部来源路径和分享保存目标未做端到端自动化；本轮测试了恢复预览取消、确认恢复与可找回恢复点。
