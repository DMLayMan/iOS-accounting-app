# 沉淀包验证记录

日期：2026-09-11。本次新增方法、案例、模板、Skill、文档导航及其校验脚本/CI 步骤，不修改余记业务代码。

## 验证范围

- Skill 必须是独立可加载的包，入口按任务读取相关 reference，不依赖余记所在的绝对路径。
- 仓库维护源与本机发现目录内容一致；逐文件 SHA-256 见 [安装清单](skill-manifest.json)。
- 模板是有意留空的工作资产，不是已完成的产品规格；调用者可以按风险删减。
- 当前项目约定只增加参考入口，不替换 PRODUCT/DESIGN，不改全局 AGENTS、插件配置或其他 Skill。

结构检查和链接检查的实际结果见 [机器检查结果](validation-results.json)。系统 Python 和 bundled Python 缺少 PyYAML，官方校验器改用 `uv run --no-project --with pyyaml` 的隔离依赖环境；没有向系统 Python 安装依赖。

后续增加了 [可重复校验脚本](../../scripts/verify-ios-playbook.mjs) 与 [故障用例](../../scripts/verify-ios-playbook.test.mjs)。覆盖健康包、不刷新过期哈希、断链、文件增删、安装漂移/缺失、跨包引用和符号链接。它们在临时目录测试，不修改个人 Skill；可移植检查进入远端 CI，本机安装核对仍是显式的本地步骤。

## 适用性桌面推演

以下是作者在当前上下文中逐项检查规则后的推演，**不是独立 Agent 盲测，也不是新增 App 已实现或验收**。它用于发现误触发、越界和过度泛化；不能量化真实节省时间。

| 输入请求 | 按本 Skill 推演的第一步与产物 | 检查到的边界 |
| --- | --- | --- |
| “开发一个自己的待办 App，简单顺手” | 确定捕捉任务/今天回看等主任务；区分项目和跨项目标签；先做创建、保存、回读、完成撤销切片 | 不强制一个二级分类、五 Tab、中央加号；提醒和重复规则按需求另定 |
| “这个取消按钮文案改短一点” | 读取当前页面与文案语义，做小范围修改和必要检查 | 不创建功能简报、不全量跑所有 UI、不重做导航；Skill 可不触发 |
| “统计看明细再加一个七分屏” | 若是明确指定的新要求则遵循；若在探索动线，先区分同页筛选和独立对象详情，再给出取舍 | 不以历史偏好覆盖当前用户明确方案；不把 70% 写成全局强制值 |
| “为日程做重复事件编辑” | 先明确单次/后续/整个系列和时间语义，再定义编辑与恢复路径 | 不套用账本 Day、退款、CNY 模型；高影响语义未清楚前不迁移历史事件 |
| “无自建服务端，直接把本地库开 iCloud 共享” | 明确同账号同步/跨账号共享、状态所有权、冲突、邀请与撤权；核实实施时的官方能力 | 不把本地开关说成同步完成；不让多个写入者各自覆盖整份 JSON |
| “主题换紫色，其他保持当前设计” | 复用现有 token 并检查根页、弹层、桥接组件和浅深色 | 不把收入/错误色跟着主题一起改变，不添加动画和页面 |
| “回归通过，把文档保存好” | 留实际提交、产物、批次与证据；按当前授权执行外部交付 | 不因 Skill 自动授权 push、合并、上架或飞书发送 |

推演中保留的关键设计：入口不加载全部 reference；共用的是状态契约而非固定界面；每项结论有证据范围；技能不要求附加插件；新产品可以选择不同导航、分类和存储方案。
