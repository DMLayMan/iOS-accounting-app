# 分类预算：设计与验收

日期：2026-09-10。当前实装目标为本地分类预算；iCloud 为[单独的架构方案](icloud-sharing-plan-2026-09-10.md)，没有把本地测试称为云同步验收。

## 使用方式

- 「账本 → 预算」或「统计 → 预算管理」→ 添加分类预算 → 每月/每年、选择分类、填金额 → 完成 → 保存预算。
- 一级分类包含当前全部二级分类；也可只给一个二级分类设额度。父子规则可以同时存在，但各自提醒，不能相加成总预算。全账本额度与分类额度同样独立。
- 可添加 0 到多条规则，不设置人为条数上限；同一分类每月、每年各一条，避免重复提醒。金额可为 0，空金额不能完成规则。
- 点击规则可改范围、周期、金额；可从编辑页移除或左划移除。变更先暂存在预算表单，点“保存预算”一起提交；取消可放弃，写盘失败整体回滚。
- 创建账本仍可直接填全账本月/年预算。分类规则在创建后的预算管理中配置，让首次创建保持简短，并以实际分类 ID 关联。

## 展示与计算

统计月/年页只取相应周期的规则；按超出金额从高到低，默认显示最多 2 条。还有超额时提示剩余项数，点“全部 N 项”在同页展开含未超额规则的完整信息，可收起。没有超额则显示“N 项预算均未超出”，不把每条进度都挤到饼图之前。

记账页只显示所选二级分类及其一级分类相关的月/年预算，不展示其他分类的告警。输入金额后用保存后的净支出计算；默认也最多 2 条，更多原地展开。总预算仍显示在金额下，超额不阻止保存，草稿不占用额度。

净支出 = 支出 − 退款，退款按实际日期返还原消费分类。编辑预览先剔除原交易，再应用新金额/分类，切换分类不会重复扣预算。全账本预算只计算一次流水，不把父子分类用量相加。规则修改从本月/本年起生效；移除通过结束规则实现，保留早期周期。分类改名保持 ID，移动二级分类后的一级汇总和既有统计一样按当前归属重算；本轮不增加历史分类关系快照。

## 数据与引用保护

沿用 Ledger.budgetRules，新增可选 categoryID：缺省为全账本规则，有值为一级/二级分类规则。按范围、周期、生效日期区分版本。备份 schema/format 升为 3；v1/v2 无该字段时仍解释为全账本规则，旧版应用应拒绝 v3 备份，不能静默吞掉分类范围。

导入校验预算范围引用必须属于同账本支出分类；同范围同生效周期不能重复。分类即使没有交易，只要存在预算历史引用也不能直接删除，可归档或移除当前规则；归档后仍保留历史预算查看。收入、转账和跨账本分类不能作为新规则范围。

本轮审查已处理：

- 总额度未设、但分类规则已设时，使用“未设置账本总预算”说明具体范围。
- 编辑页增加常驻的“预算金额（元）”标题，填入金额后不会丢失单位提示。
- 分类管理的引用提示包含预算；有预算历史引用的分类提供归档入口，不误提示为可直接删除。
- 非法金额、重复范围的“完成”按钮保留禁用与提交校验。原生调试树确认 Toolbar 的外层 Other 容器保持 enabled，而内层 Button 为 Disabled；早期测试错误读取外层，已改为断言真实 Button，并保留截图/层级证据。

限制：真机触觉、完整 VoiceOver 与 iCloud 跨账号同步未在本轮验收；未来同步还需开发团队、容器、两账号设备及冲突测试，详见共享方案。分类变更按当前关系重算汇总，不提供历史关系快照。
