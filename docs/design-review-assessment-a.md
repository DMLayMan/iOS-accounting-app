## 设计判断

**研判：余记已形成适合个人记账的清爽基础，但关键操作之间还没有形成一致、可信的体验。** 白底、克制的绿色、突出金额、二级分类和底部数字键盘都有明确用途；不需要再增加卡片、阴影或装饰性图表。最有价值的改进是让用户一直知道自己正在查看哪本账、哪段时间、哪个分类，以及一次保存或恢复究竟有没有完成。

设计有产品针对性：计算式金额、退款关系、分类与账户组成了记账场景，而非可随意换内容的通用仪表盘。主要削弱点是普通流水图标退化为统一箭头，统计把同一项分析切断为多个面板，以及基础管理页与核心录入页的结果反馈不同。

## 做得好的三点

1. **录入页把钱放在首位。** 金额、分类、账户/日期、可选备注组成短路径；绿色只用于操作和选择，普通支出保持黑色，快速记账不需要阅读大段说明。
2. **已有数据关系对用户可见。** 支出详情展示原金额、已退、可退额度和关联退款；统计同时交代毛支出、退款与净支出，避免一个没有口径的总数。
3. **草稿退出已有良好修复。** 新建与编辑采用不同退出语义，确认出现在键盘原位置；深色辅助字号截图能完整显示继续与清空动作。这套“失败留下、成功退出”的原则应扩展到管理页。

## 除本次两项要求之外，五个优先问题

### [P1] A1 · 恢复操作没有审阅点，备份状态早于文件交付

**证据：** `MeAndData.swift:252–260` 选文件后直接调用恢复；`AppState.swift:211–227` 校验后写入并换库。`AppState.swift:194–202` 在临时文件生成、系统分享前更新 `lastBackupAt`；`MeAndData.swift:264–267` 临时文件写失败只返回 nil。

**影响：** 用户选错一个格式正确的旧备份就会替换现有数据；取消系统分享后仍看到“最近备份”，容易误以为已有可找回的文件。这不是后端原子性问题，而是用户无法看清影响与完成状态。

**修复：** 导入后先显示备份日期、账本/记录数、将替换哪些本地数据，并提供取消/恢复；恢复前可自动保留当前库的恢复点。状态改为“最近生成备份文件”，或在系统明确返回交付成功后再记录“已导出”；临时文件失败保留在数据页显示可重试错误。不要把分享控制器出现当作文件已保存。

**验证：** 选旧文件后取消不改变当前账本；取消分享不出现已导出；临时文件写失败可见且可重试。建议命令：`/impeccable harden`、`/impeccable clarify`。

### [P1] A2 · 账户表单把无效金额吞为零，保存失败仍退出

**证据：** `ManageViews.swift:112` 使用 `Decimal(string: openingYuan) ?? 0`；`115–125` 忽略 `state.perform` 返回值并无条件 dismiss。归档在 `79–83` 同样如此。

**影响：** 用户刚输入的账户内容消失，关闭动作像是保存完成；空输入与格式错误没有被区分。相同 App 的主录入在失败时留在原页，管理页却违反这一预期。

**修复：** 区分空白默认零和无法解析的金额；金额错误就近显示，保留输入。只有 `perform == true` 才关闭；归档失败留在当前页。给期初调整显示旧值→新值及余额影响摘要。无需新增复杂操作步骤。

**验证：** 非数字粘贴不写入零；磁盘失败时名称、金额、日期都在；重试成功才关闭。建议命令：`/impeccable harden`。

### [P1] A3 · 普通表单/主录入未形成统一的大字号与深色可读性

**证据：** `Design.swift:45–64` 与 `AmountText` 使用固定字号；`EntryView.swift:84` 账户日期行高度 30 pt、`160–162` 类型按钮最低 32 pt，`250/256` 辅助信息为 10 pt。`RootView.swift:30` 直接 tint 为浅色 sage；多个管理页也直接用 `Design.sage`。旧深色偏好/回收站截图可见绿色文字偏暗。当前源码能证明缺少自适应策略，截图不能证明所有真机触点实际尺寸。

**影响：** 已为统计和退出确认做的大字号适配只覆盖局部。用户增大字号后主录入仍小，而管理表单变大，视觉节奏与可点击性不一致。

**修复：** 正文与标签用系统 text style；金额可用 scaled metric 配合换行/缩放边界；辅助字号下账户日期竖排、分类列数降低。账户/日期/类型动作的真实点击区至少 44×44 pt。深色统一走 `Design.primary(scheme)` 或语义 AccentColor，保留视觉品牌但不靠同一浅色 token 硬撑。

**验证：** Pro+SE 各检查默认与最大辅助字号、浅深色；所有关键字段可读，金额不截断，VoiceOver 能独立操作账户、日期、保存。对比度需实际取色或工具测量，本报告不宣称已测得比例。建议命令：`/impeccable adapt`、`/impeccable audit`。

### [P2] A4 · 全局加号与重复统计入口让导航上下文不够稳定

**证据：** `RootView.swift:32–48` 用 ZStack 在整个 TabView 上叠加按钮；旧首页/详情/设置截图中加号均压在 tab 区域上方。`LedgerHomeView.swift:83–84` NavigationLink 推入另一个自带 NavigationStack 的 StatsView，而 Root 已有统计 tab。

**影响：** 同样“统计”有两套月份/选择状态；加号在修改设置、核对退款等支线也持续抢占视觉。旧截图只能证明空间接近，当前是否实际截获 tab 点击仍待现场验证。

**修复：** 首页“看统计”切换既有统计 tab。保留易触达的记账主动作，但给其独立安全区域或合适的原生工具栏位置，避免覆盖 tab 触点；支线页如继续显示，必须有明确让位与安全区策略。保存后优先回到用户原上下文，并给成功反馈。

**验证：** 首页和 tab 进入统计共享同一个周期状态；SE 上流水/统计 tab 和加号均可独立点击；详情返回维持原筛选。建议命令：`/impeccable layout`、`/impeccable polish`。

### [P2] A5 · “外观与反馈”的两个开关未兑现操作承诺

**证据：** `MeAndData.swift:276–279` 只存 `hapticsEnabled/reduceMotion`。全 UI 搜索未发现其他读取；`InlineCategoryStrip.swift:106/127` 无条件触发选择/拖动触觉，`YujiApp.swift` toast 仍声明顶部移动转场。

**影响：** 用户明确关闭反馈后仍收到反馈，设置页的可控感失效。辅助功能偏好尤其不应只是摆设。

**修复：** 将触觉配置传入原生分类组件并在触发前判断；所有自定义动态读取系统 Reduce Motion 与 App 设置，使用较轻的透明度变化。若某项尚未实现，先移除该开关并保留真实支持的外观选择。

**验证：** 用可注入触觉服务验证关闭后不触发调用，真机确认开启/关闭体验；Reduce Motion 下无自定义大幅位移。建议命令：`/impeccable harden`、`/impeccable animate`。

| 单次选择不超过 4 个未分组动作 | 部分未满足 | 分类屏同时有 6–8 个一级项、最多 8 个二级项及编辑/全部/新增；层级与横向分页已缓解，但编辑态不应再保留无关数字键盘 |

| 一个主操作 | 基本满足 | 数字区保存突出；详情页编辑在底部，同时全局加号存在，主目标有竞争 |
| 当前上下文始终清楚 | 部分未满足 | 首页账本明确，其他 tab 多数只显示页名；多账本用户应能在统计/流水快速识别当前账本 |
| 错误保留工作 | 部分未满足 | 记账/退款较好，账户表单失败退出、备份临时写文件失败无反馈 |
| 术语贴近任务 | 部分未满足 | “先校验再切换”“关联记录或草稿”“基期”在需要处简短解释；转账预览提到“预算”但当前可达页未发现预算功能 |

**情绪路径：** 打开首页的大金额让用户迅速掌握现状；录入分类与数字键盘形成完成感；草稿恢复和退款额度提供安定感。旧统计弹层是分析过程的低谷；错误后自动退出和恢复替换则是信任低谷。最值得保留的结束体验是“已保存→原上下文立即更新”，不需要庆祝动画或更多成功弹框。

## Persona 风险

- **Casey，单手、易被打断的用户：** 关闭留草稿非常适合该场景；账户/日期的 30 pt 行与顶部保存仍需更大触点。退款与转账采用不同键盘，需要重新适应。失败关闭账户页会丢掉现场上下文。
- **Sam，依赖大字号/VoiceOver 的用户：** 统计辅助字号有独立布局，值得保留；录入/账户的固定字号和深色静态 tint 仍然薄弱。触觉/动态偏好未接入实际操作，使系统无法按其需求安静下来。
- **Jordan，首次记账用户：** 能理解“记一笔”“剩余可退”，但无账本/无账户时只能循文字寻找管理入口；“最近备份”不会提醒文件还没保存到可找回位置。应在每个空态给当前可完成的一步。

## 次级观察与待办

- **[P2] 明细扫描保留分类特征。** 当前 `TransactionRow.iconName` 对所有支出返回统一箭头；普通支出/收入可使用存储的分类 SF Symbol，退款/转账继续保留特殊操作符号。图标和文字必须使用同一个分类来源，避免本次图标编辑只改录入页。
- **[P2] 编辑入口放到详情导航栏。** 大金额与分类重复出现占据首屏，编辑在退款区之后；保留完整关系，缩减重复标题，把编辑放在明显的 toolbar 即可减少滑动。
- **[P2] 归档账本应显式只读。** 切换器包含归档账本，主界面仍有新增/转账入口；应显示只读状态并把无效操作替换为“恢复账本”。能否实际提交由领域层阻止，本次未运行，不以推导替代测试。
- **[P2] 退款纠错路径待核实。** 原支出有退款时删除文案要求“先处理退款”，但当前退款详情没有编辑/删除入口（`DetailAndRefund.swift:113–120`）。需要明确允许怎样撤销错误退款；这是行为规则决策，不应只美化报错。
- **[P2] 搜索的实际范围要一致。** 当前字段只说搜索一级/二级分类；模型仍有日期、账户、金额范围但 UI 不可设置。按当前需求先保持明确的分类搜索，不在本轮凭空增加复杂筛选。
- **[P3] 管理入口命名。** “历史附加信息”保留旧数据是合理的，但可用“原有标签”并用短说明交代当前不再新增，降低用户困惑。
- **[P3] 日期与金额格式统一。** 首页、流水、明细、管理页使用多套日期格式；旧账户截图出现年份 `2,026`。当前 SwiftUI 插值是否仍千分位格式化待实际验证，日期应走统一格式函数。
- **[P3] 空态给动作。** 无账本→创建账本；无账户→新增账户；无结果→清除筛选；无统计→记一笔或换周期。无需画插画或再造引导页。

## 交付优先顺序

先完成用户明确的分类编辑与统计同页联动，再补 A2（表单失败一致性）、A3（触点/字体/深色统一）、A4（单一统计入口），随后处理 A1 的备份交付和恢复审阅、A5 的真实偏好行为。A1 若进入真实用户使用范围，应在发布前完成。
