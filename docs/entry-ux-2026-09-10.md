# 余记：记账入口与标签体验改造

> 后续决策已改为单一二级分类，本记录保留为历史。当前实现见 [统一分类方案](category-unification-2026-09-10.md)。

日期：2026-09-10。范围：原生 SwiftUI 录入页、标签选择和管理、相关数据规则。状态：已实现并更新验收模拟器，尚未安装到个人真机。

## 问题与设计判断

用户看到的“上方快捷标签”实际是单选分类，下方才是多选标签。原界面缺少明确标题，分类又统一使用标签图标，造成重复概念。不是用户理解有误，是界面没有解释清楚。

分类回答“钱花在什么类型”，例如餐饮、交通；标签回答“这笔记录还属于什么场景或项目”，例如出差、朋友、装修。一笔支出选择一个分类，标签可以没有，也可以多个。分类用于互斥汇总，标签用于交叉查看。合并成同一种多选标签会使默认分类统计产生重叠。

研判：保留两种数据含义，统一真正的标签入口与目录，避免让用户学习两套标签操作。

| 维度 | 原问题 | 本轮实现 |
| --- | --- | --- |
| 概念 | 分类和标签看起来相同 | 分类明确标注“分类 · 选一个”，使用不同类别图标；标签只有一个入口 |
| 录入动线 | 常用项固定、字段占空间 | 分类按近期使用排序，当前选项保持可见；账户与日期合并为一行 |
| 输入状态 | 自定义金额键盘与系统键盘同时出现 | 输入备注、打开标签/分类/日期/账户选择时隐藏金额键盘；备注行提供完成动作 |
| 标签选择 | 快捷与输入分散 | 同一页面承载已选、最近使用、搜索、新建；列表之间不重复展示同一项 |
| 创建 | 需要提前维护 | 搜索无同名项时直接新建并选中；已存在的规范化同名标签复用 ID |
| 修改 | 历史关联容易不明确 | 改名保留 ID，历史记录显示新名称；同一账本不允许新建或改成重复叶子名称 |
| 停用 | 删除可能破坏历史 | 归档隐藏推荐、保留历史；允许恢复；删除只提供给没有交易/草稿引用且当前未选中的标签 |
| 取消/返回 | 临时选择和录入内容可能被带入或覆盖 | 完成才提交选择；取消丢弃临时勾选；录入内容只在首次出现时初始化 |
| 类型切换 | 恢复收入草稿时可能重置分类 | 只有用户切换收支类型时重置分类，读取草稿不触发 |

## 标签交互约定

1. 录入页点击“添加标签”，进入唯一的标签选择器。已有标签时展示选中名称。
2. 未搜索时按已选、最近使用与常用、其他标签展示。最近使用基于账单更新时间，受当前账本隔离。
3. 搜索匹配已有标签；无同名项时可新建并选中。新建默认进入“自定义”分组，保留原有两级数据结构。
4. “完成”提交选择，“取消”仅取消选择。新建、改名、归档是立即保存的目录操作，不随取消选择撤销。
5. 页面右上角“管理”与设置中的“标签管理”共用同一组件，避免两套 CRUD 行为。
6. 归档默认保留历史。删除前检查交易（含回收站）、草稿及父标签的子节点引用，引用存在时拒绝删除；检查失败不做部分删除。

## 参考与取舍

- [Copilot：Tags vs Categories](https://help.copilot.money/en/articles/9554367-tags-vs-categories)：分类与标签承担不同分析维度。余记采用明确的分类单选和标签多选表达。
- [Copilot：Tags](https://help.copilot.money/en/articles/9554342-tags)：参考统一管理、创建时应用、避免重名的思路。其手动交易添加标签的时机与余记不同；余记支持保存账单前选择或新建标签。
- [Lunch Money：Categories & Tags](https://lunchmoney.app/features/categories-tags)：参考分类与跨分类标签并存的组织方式。
- [Apple：Selection and input](https://developer.apple.com/design/human-interface-guidelines/selection-and-input)：输入方式应服务于当前任务。本轮以输入焦点控制键盘，减少同时出现的输入面板。

以上是交互原则借鉴，没有照搬其他产品界面；第三方产品的价格、完整功能不属于本次核验范围。
