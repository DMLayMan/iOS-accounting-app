## 真实验证发现并修复的问题

触发：B 的自定义昵称写入自己的 private default zone 后，再从共享成员记录读取。

现象：私有资料保存成功，共享回读却找不到相同身份。CloudKit 把当前参与者的 `userRecordID.recordName` 表示为 `CKCurrentUserDefaultName`（当前系统值 `__defaultOwner__`）；直接拼接身份后，与 `container.userRecordID()` 得到的真实账号身份不同。

修复：成员身份统一先解析此系统别名，再生成昵称 record ID、显示成员名或判断邀请自己的账号。其他成员的 opaque 记录 ID 保持不变；交易 authorID 不迁移、不重写。新增两个纯原生身份测试。修复后真实回读中恰有一个成员匹配当前账号，私有和共享昵称一致。

测试夹具还修正了一处独立错误：QA run UUID 并非账本 zone UUID。现在读取此前真正接受邀请时保存的 member-address，严格比较已登记 zone，不从 run 或 owner 字符串猜地址。原拒绝范围失败、昵称回读失败、原始快照和修复后结果均保留。

## 测试驱动问题与重跑记录

本次接续没有修改已上传的 App 实现；147 个冻结文件在文档更新前重验全部一致。只调整独立 UI 驱动，并保留所有早期失败：

- 首次 addA 把显示“¥0”误判为非零，保护断言在输入前停止；交易仍 3 笔、草稿为空。核对实际格式后只接受“¥0”或“¥0.00”，非零及非空备注仍停止；重跑成功且只新增一次。
- 首次 restoreA 将空输入的 AX value“输入昵称”与空字符串直接比较；修正为空值/placeholder 归一化。后续重跑时遗留键盘遮挡底 Tab，XCTest 计算到无效命中点并触发听写，默认中断处理又打开 Siri 隐私说明。回收 AX 后关闭说明、只选已读到的“以后”，没有启用听写；先按键盘“完成”再导航，并改用原生“使用 iCloud 姓名”恢复，最终重跑通过。空值、焦点和控制可点击性是驱动前置条件，不能盲点屏幕或通用“第一个按钮”。
- 第一次冷启动命令的空 environment-variables 对象被 devicectl 拒绝，没有发生冷启动；保留退出 64。确认未继承 DEVICECTL_CHILD_ 后去掉该可选参数重跑，成功启动，再执行新增及新昵称 UI 断言。早期名字为 cold 的结果包仅证明当时暖启动互看，实际冷启动依据 `a-cold-launch-retry.json` 和 `a-addA-retry.xcresult`。

UI 多阶段仍为同一个参数化方法，B 多阶段亦为同一个真实云方法；阶段执行次数不相加为独立用例覆盖。
