# 共享记账人和统一昵称

日期：2026-10-15。需求：同一 iCloud 账号统一昵称，用户可主动修改；一笔流水能看出创建人。

## 行为与界面

- 我的 → 偏好 → 我的昵称 → 填写 → 保存。保留页面顶部支持入口的优先级，不新增身份注册、头像上传或弹层。
- 先使用 Apple 在当前 CloudKit 身份中提供的姓名，用户昵称覆盖默认姓名；清空后恢复默认。Apple 不保证提供姓名，缺失时本人显示“我”，已加载的其他成员显示“成员 N”；未加载的历史成员显示“共同记账成员”。昵称不能当作匹配账号的依据。
- 昵称最多 20 个字符（按 Swift Character，即扩展字素簇计数），支持中文、emoji，去掉首尾空白，禁止内部换行和控制字符。保存失败保留输入。
- 共享流水副标题首先显示记账人，之后是日期（需要时）、账户和备注；个人本地账本不增加冗余人员标记。详情显示记账人，以及不同于创建人的最后修改人。自己的名字附“（我）”。
- 历史记录缺失 authorID 时明确显示“未知记账人”，之后编辑也不能猜填创建人。对已有记录，任何本地修改都保持原 authorID（包括 nil），只更新 lastEditorID。新建云账本记录使用当前已核对的 opaque iCloud 身份。
- 改名立即更新本机展示，私有资料和每个可编辑账本异步同步；失败保留本机待发送意图并允许重试。只读成员可修改自己的账号私有昵称，但不能向只读账本更新共享资料，会显示限制说明。

## 存储与兼容

1. LedgerData 增加可选 cloudPeople，记录按当前 accountID 隔离的私有偏好、待发送 revision 和逐账本成员缓存；不改变 schema 4。旧文件字段缺失仍可读取。备份生成与恢复都去掉此缓存和待发送操作。
2. 个人全局昵称：CloudKit private database 的 default zone，记录 yuji-my-nickname。其他账号不能查询这个私有资料。
3. 成员展示投影：每个已有 yuji-book-* 自定义 zone 内单独的 member-<SHA256(accountID)> 记录。共享参与者只读已接受成员的资料；不建公共昵称目录。账本 financial payload 和格式 1 保持原样，旧客户端只写 ledger 记录，不会吞掉昵称字段。
4. 复用已部署的 YujiLedger 存储 envelope 及已有 payload/name/formatVersion 字段；资料 payload 用 kind=yuji-person、version=1 区分，限制 16KiB 并校验 subject。复用的是云存储格式，不把昵称当作财务领域实体；后续迁移可替换适配器。默认 zone 不支持原子批次，单记录写入用非原子批次加 change-tag 条件保存。
5. 私有意图先落盘再联网。多个设备同时改昵称，按最后成功提交的偏好生效，不增加账目冲突弹窗。cloudEpoch + accountID 防账号切换串写回；revision 防旧异步请求清掉新昵称。改名只写展示元数据，不修改任何交易、财务 revision、金额或支持邀请计数。昵称缓存落盘不清除有效的账单撤销回调。
6. 昵称同步与财务同步的错误状态分离；自动最多每 120 秒刷新，显式检查和保存可立即重试。多个账本分别处理失败，不能因为一本无权限或离线卡住其他账本。

## 权限和局限

- 无自建服务端、公开资料数据库、通讯录权限或 Key-Value Store entitlement。
- 昵称是展示资料，不是实名验证或防篡改审计。CloudKit 读写成员可修改共享记录，仍沿用相互信任的小组边界。
- 只读账本不能广播成员的新昵称；不要为了显示昵称放宽财务权限。拥有者改成可编辑后，后续同步可补发。
- 协作者使用尚不支持昵称的旧版本时仍只显示通用称谓。离线、暂停、账号未验证以及 Apple 未提供姓名都有相应回退。
- 已离开的成员、刚加入的新设备未缓存的旧作者可能只显示通用称谓；opaque 创建人身份仍保留，不会错误归到其他成员。
