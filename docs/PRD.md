# 余记 PRD · 当前实现规范

更新：2026-10-16。面向个人长期使用的原生 iPhone 应用。本文是当前实现的产品基线；日期命名的历史迭代文档不覆盖本文。[页面复刻](UI-SPEC.md)、[设计规范](../DESIGN.md)、[架构](ARCHITECTURE.md)、[本轮验证](release-validation-2026-10-15/README.md)配套使用。

视觉收尾：统计默认人员入口与净支出标题合并，实际统计期间始终可见；无退款不重复显示减零公式，有退款保留分解。长昵称及大字模式继续独立排布。流水的备注与人员/账户信息分行，详情完整显示；备注仍不参与搜索或统计。我的将最近删除并入账本组，偏好提前，备份与 iCloud 放入数据与同步组，支持仍为第一项。账本大字标题/操作纵向排列，记账收支选择增加非颜色提示。见 [最后一轮设计复审](final-polish-2026-10-16/README.md)。

本轮交互规则：冲突比较覆盖全部有差异实体，预算按范围和生效周期比较；不截断为最近五条，不提供新的自动覆盖/逐字段合并。昵称保存后显示本机持久化及同步状态，再由用户点完成返回；只读账本影响提前说明。统计明细保留记账人条件及清除入口，与顶部筛选状态同源。正常预算压缩、详情按需展开，超额仍最多两项默认露出。支持金额继续展示 Apple 原价，主动刷新不发起购买，当次数值报价变化须重新点击确认；历史报价缺失不推定一致。详见 [本轮实现与验收](release-validation-2026-10-15/build13-polish.md)。

名称：商店、桌面安装名和拟备案名称统一为「余记账本」，应用内品牌保留「余记」；用户于 2026-10-13 明确确认。签名候选包显示名已核对；备案已由本人提交，按要求等待审核。发布状态见 [本轮发布验证](release-validation-2026-10-15/README.md)。

最新修复、原生回归与剩余发布条件见 [2026-10-15 发布验证](release-validation-2026-10-15/README.md)；[10 月 8 日全量复审](review-fix-2026-10-08/README.md)、[10 月 3 日审查](release-audit-2026-10-03/README.md)保留历史问题和失败证据。本文不构成已通过上架验收的声明。

## 1. 目标、范围与原则

目标：少步骤记录，保留分析上下文，数据可解释、可迁移、可恢复。iPhone 竖屏、iOS 17+、CNY。首阶段无独立应用账号、无自建后端。所有分类推荐、统计、预算、主题均本地运行。iOS 17.5 模拟器兼容性已验证；实体 iOS 17 设备和真机 VoiceOver 听读不在该结论内。

本版本提供多账本、多账户、收入/支出/退款/转账、两级分类管理、草稿、查账、统计下钻、预算、回收站、备份/恢复/CSV、外观设置及自愿支持开发者。可选 iCloud 同步/共享已实现，Development 双账号核心共享与真实 Sandbox 支付已有独立证据。Debug 默认关闭云适配，Release 默认启用 Production 权限；账本仍由用户逐本选择开启同步。10 月 15 日 Schema 已部署 Production、1.0 (4) 已签名并上传，真实生产服务与 TestFlight 安装验证仍分别推进。自动导入银行流水、重复计划、预算结转、CSV 导入、桌面小组件不属于已交付能力。

体验约束：明确的任务入口；不通过额外弹层解释本可同页显示的信息；保存成功后才退出；错误时输入留存；费用类型不用颜色单独编码。

## 3. 账本与账户

账本页展示当前名称、切换/新建、累计收支、账户余额、记录概况及草稿入口。累计范围为首笔至今天；不在首页重复排列逐笔流水。看统计/查看流水转到对应根 Tab。

累计收入 I、累计净支出 N、累计结余 I−N 不含期初和转账；账户余额包含已生效期初及转入/转出，包含归档账户的历史余额。账本页与账户管理均截至今天，未来期初显示“期初尚未生效”，未来流水暂不计入当前余额。页面明确“含期初余额”和统计截止日期。

新建账本为 70% 高度可展开表单：名称必填，月/年预算可空；完成输入收起键盘后点“创建并使用”。创建账本、默认目录、预算及当前账本切换一次提交。失败保留原账本和表单。支持改名、归档/恢复；至少保留一个未归档账本。归档账本可查看与导出历史，不新增交易。只有无任何交易（包括回收站）的非唯一可用账本可删除；删除连带清除该空账本目录与草稿，界面明确确认。

账户支持新增、改名、期初余额与记账起点、归档/恢复。期初可为负；范围 ±999,999,999.99 元。起点不可晚于已有有效流水；新交易不可早于相关账户起点。转账同时检查两端。当前账户界面以归档管理停用；领域层也禁止物理删除被交易或草稿引用的账户。归档后历史保持可读，新增选择器不再提供。

补记早于账户起点的收入/支出时，记账页就地展示账户起点完整年月日与「调整记账起点」。进入复用的账户表单，预填该笔日期并说明期初金额保持不变、生效日期随起点调整；保存账户后回原记账页，保留金额/分类/日期/备注，仍由用户另行保存交易。取消原样返回，不静默修改已有账户起点；只读共享成员不可调整。零/非零期初、跨年、落盘失败、取消和重启均须覆盖。详见 [10 月 15 日发布验证](release-validation-2026-10-15/README.md)。

全部账户已归档时，记账选择器解释缺少可用账户及我的→账户新增/恢复路径；现有输入关闭后保留为草稿，账户未选定不可保存。

## 4. 分类与备注

支出与收入分别有独立的两级目录。每笔收入或支出必须指定一个二级分类；一级仅用于组织、预算和聚合。转账不选分类；退款沿用原支出分类。备注可输入并在详情/流水辅助展示，但不参与搜索、筛选和推荐。

记账页一级一行横向排列；二级每页四列、最多两行，先从左到右，再到下一行。不足五项只占一行，超过八项横向分页。新增按钮固定在二级区域侧边；不挤成额外的二级分类。全部分类保留，用于搜索、定位和管理。

长按一级或二级进行原生拖动排序；边缘拖动可切换二级页。排序提交只改同级稳定顺序，不改交易归属。可以撤销本次排序；重启持久化。一次录入中不会因金额或选择变化自动重排点击目标。旧常用推荐数据仅辅助默认选择，手动排序具有明确控制权。

新增/编辑共用分类表单：图标预览、名称、所属一级、图标网格、保存。高度初始 70%，可展开；键盘出现允许展开。图标本地 SF Symbols 白名单。名称去首尾空白，不能为空，同层同名忽略大小写拒绝；不同一级可有同名二级。新增成功回原录入并选中新分类。取消修改显示页内继续/放弃，不再叠加气泡。

支持一级/二级改名、二级换组、图标、归档/恢复、删除。引用中的分类（交易、草稿或历史预算）保留，通过归档停用；不静默删除历史或自动合并。一级归档影响其下级可选状态。旧标签模型及 ID 为备份兼容保留，入口和新建表单不存在第二套标签。

## 5. 记账、草稿与编辑

高频路径：底部记账 → 输入金额 → 选二级分类 → 保存。日期默认今天、账户采用可用默认值；切换收入保留清晰类型提示并切换目录。可进入账户、日期选择与分类编辑。

金额使用十进制算式计算器，最终存整数分，允许 0.01～999,999,999.99 元。无效/除零/超范围不可保存；超过两位小数显示四舍五入后的明确保存金额。整数分是账务真值，格式化只用于展示。

金额键盘与备注系统键盘互斥。文字编辑期间隐藏金额键盘，完成后恢复；关闭、取消和离开子表单先结束文字输入。小屏允许上方表单滚动，关键保存动作仍可到达。

新建关闭或进入后台时保存本账本草稿检查点；没有内容不创建草稿。草稿包含金额表达式、类型、日期、账户、分类、备注；不进入余额、统计、预算和有效流水。检查点比较当前输入与最后落盘草稿，新建输入在后台保存后又撤回为空表单时清除旧检查点，避免重启复活撤回内容。保存成功清除此账本草稿；失败既不关闭也不清草稿。编辑已有交易不覆盖新建草稿。转账不清除独立的收入/支出草稿。前台直接强杀未触发生命周期时，不承诺逐键恢复。

已有收入/支出可编辑；有退款的支出修改受剩余额度、类型、日期关系约束；失败就地说明。已删除记录须先恢复再编辑。编辑取消有改动时在当前页面底部显示“继续编辑 / 放弃修改”，不弹出遮挡金额的气泡。

## 6. 转账、退款与回收站

转账：账本 → 账户余额区转账 → 选转出/转入、金额、日期 → 预览两端影响 → 保存。必须同账本不同账户；一条原子记录影响两端余额，不产生两条收入/支出，不计预算。空表单取消直接退出，有修改才确认。算式舍入时保存按钮明确最终金额。

退款：支出详情 → 记一笔退款 → 默认剩余可退金额 → 确认到账账户/退款日 → 保存。退款可到同账本其他可用账户；发生日不能早于原支出。有效退款合计不超过原金额。退款用实际发生日计入原支出分类，跨月可使某月净支出为负。不能单独创建无原支出的退款。

退款详情可跳原支出，也可删除错误退款，再重新记录；删除退款释放可退额度。有有效退款的原支出不能删除，先处理退款。支出、收入、退款、转账均支持软删除；3.5 秒撤销提示，之后从最近删除恢复。恢复重新校验账户、起点、原支出和退款额度，失败保留回收站记录。

永久删除必须确认。仅回收站记录可永久删除；原支出被任意退款（包括回收站）或草稿引用时不可永久删除，避免断链。永久删除不可撤销。批量领域操作保证整批通过或全部不变，当前页面是否提供入口以 UI 清单为准。

## 7. 流水与时间选择

流水为查账入口：时间栏 → 笔数/收支摘要 → 已选条件 → 按日倒序记录。界面可组合类型、分类、分类名关键词、账户及单笔金额上下限；不搜索备注。账户包括历史归档项；转账匹配任一端。金额可单边填写，含边界，空值不限制，0 为有效下限；非法值或最低金额大于最高金额时解释原因并禁用导航栏固定的“应用”。应用才提交，取消保留旧条件，清除恢复无条件查询。明细返回保留条件。空月与无匹配条件有明确空状态和清除入口。转账用单条记录表达。

流水/统计共用完整 `PeriodNavigation`：上方“月 / 年 / 全部 / 范围”系统分段；下方居中年月及左右圆形切换按钮。前后按钮点击区域至少 44pt。按自然月/年连续前后切换，不跳过空月；跨年自动更新年份。全部和范围不显示前后按钮。

点日期打开 `PeriodPicker`，月：选年份+十二个月，点月即应用；年：直接选年；全部：立即应用；自定：填写起止后应用。取消不提交，恢复真实期间及分段选中态。不保留历史版本的滚轮、侧边定位条或额外滑动提示组件。

**流水显示完整所选期间，包括未来记录；统计只显示截至今天的实际记录。** 两页日期选择相同不代表实际截止口径相同，统计始终显示实际日期范围；全未来期间不冒充“零支出”。

## 8. 统计、下钻与同比环比

统计顺序：共用时间栏 → 记账人筛选 → 期间金额 → 预算（适用时）→ 月度同比环比或年度同比与月份趋势 → 构成与排行 → 同页明细/筛选。以页面实际可滚动区为准，不额外打开“查看明细”七分屏。

记账人默认全部，可选本账本有有效收支/退款记录的人员或未知记账人；按创建人 authorID 过滤，非最后编辑人、昵称或实际付款人。改昵称不改变筛选身份，历史 nil 不推断归属。期间汇总、同环比两期、年趋势、分类图/排行/变化和明细统一过滤。退款属于退款记录创建人，日期取退款发生日、分类仍取原支出。时间切换保留人，账本切换重置全部，人员变化清除分类下钻。预算保持整本口径，选人时隐藏预算卡并说明回到全部查看。详见 [构建 10 规格与验收](release-validation-2026-10-15/build10-delivery.md)。

| 指标 | 定义 |
| --- | --- |
| 支出 E | 区间内有效支出总额 |
| 退款 R | 区间内有效退款总额，按退款日 |
| 净支出 N | E−R，允许负值 |
| 收入 I | 区间内有效收入总额 |
| 结余 S | I−N |
| 账户余额 | 期初+收入−支出+到账退款+转入−转出 |
| 分类占比 | 该分类毛支出/全部毛支出，或该分类收入/全部收入 |

期初、转账、草稿、回收站不进入收支统计。分类叶子互斥，一级等于下级并集；按分类汇总守恒。退款单列，不能把负净额作为饼图扇区。仅退款、无毛支出期间，饼图无可分配扇区，但退款行和明细仍可查。

点饼图/排行选一级，二级筛选及下方汇总、明细同页更新；再次选中可取消，切换类型/期间不遗留无效选中项。排行默认前四类，可展开；按金额/笔数/退款排序，收入不展示无意义退款排序。排行“笔数”指原收入/支出记录数量，退款金额独立列示；下方流水笔数可包含退款，因此不得混称。仅点击单笔流水才进入详情，返回保留筛选。月趋势点击对应月份，期间与内容共同切换。

环比/同比以**净支出**比较，不评价“好坏”：变化额 C−B；仅满足可比条件且 B>0 时显示百分比 (C−B)/B×100%。本月对基期相同进度；历史月比较两个完整自然月。若本月已过天数超过基月天数，用共同天数并提示，不显示增长率。基期为零、负、早于记账起点均解释原因，不显示虚假百分比。

本年为 YTD，对上一年同期月日；闰年 2/29 的同比两边比较到 2/28，主汇总仍包含 2/29。历史年按全年。展开比较显示本期、基期日期及金额，可切换到该期间的分类构成与同页明细。基期覆盖仅表示账户声明起点，不声称历史数据完整无漏记。全部/自定不强套同环比。

## 9. 预算

每个账本可独立配置月额度、年额度；留空=不设，0=零支出计划。二者独立，不自动乘十二、不结转。修改从本月/本年开始，过去周期规则保留；同周期修改替换该生效点。统计查看历史按该期有效额度计算。

允许 0 到多条分类规则：月/年、一级支出分类（含下级）或单个二级、额度。同范围同周期只能一条；父子预算独立提醒，不相加。规则在预算表单暂存，一次保存全部提交；退出取消全部不落盘。移除从当前周期停用，历史规则和分类引用仍保留。

已用=净支出，退款按发生期返还预算。剩余=额度−已用，可超过额度（净退款）；条形进度夹在 0～100%，文字仍显示真实超额。统计预算始终为账本整期口径，不因选中图表分类而缩小分母。

分类规则默认展示超出最多的两项，其余同页展开；无超额时简短汇总。记账仅提示当前选择分类的关联规则，金额和旧交易替换预览共同影响预算；草稿不计入。超额不阻止保存，提示采用“超出”文字及语义色。全部/范围不展示无自然周期对应的预算。

## 10. 外观、可访问性与反馈

我的 → 外观与反馈：跟随系统/浅色/深色，六种主题（青竹、海蓝、暮紫、烟玫、琥珀、石墨）及系统自定义选色器。预设点击立即持久化，自定义关闭选色器时提交，失败回滚；主题不会改账务数据。深浅色自动调亮度，不保证选取的原始色值原样用作正文。

操作主题色与财务语义色分离：支出暖橙、收入青绿、退款蓝色、转账/余额中性。正负号、类型名称、选中形状并存。分类图表使用稳定分类色，与操作主题独立。

所有产品 sheet 在呈现根重新解析当前主题，分享面板与系统选色器显式使用该操作色。长账户名允许压缩省略，日期独立留宽；无障碍字号改为上下布局，完整名称保留在选择器与朗读标签中。辅助文案使用语义字号，金额键盘保留有限尺寸。

我的 → 隐私说明 / 帮助与反馈。隐私说明随安装包离线可读；帮助解释分类、预算、草稿、备份、恢复及可选 iCloud，提供公开项目反馈入口。未配置云能力时说明此安装包暂不可用，不出现可成功开启的假开关。

支持大字号和小屏滚动，金额等宽数字；减少动态遵循应用设置/系统设置。触觉可关闭。自动化触达与颜色对比测试不能替代真机 VoiceOver 听读、触觉或长期使用评价。

无障碍验收要求：流水每笔合并朗读完整类型、金额、年月日、账户、共享记账人及备注；收入排行不播报退款。日期、图标与计算按键使用中文语义，选中分类可再次取消；排序提供“向前/向后移动”辅助操作。退出决定出现时隐藏不可操作的底层表单并请求焦点；保存/撤销/支持反馈与昵称保存后的同步结果主动公告。实际发声与焦点顺序须在含修改的新包上完成物理设备听读，详见 [iOS 17 与无障碍补验](release-validation-2026-10-15/ios17-accessibility-2026-10-16.md)。

## 11. 数据安全与恢复

本地文件是完整账本快照，写入先校验再原子替换。所有 UI 数据变更经过 `AppState.perform`：内存快照 → 领域操作 → 全库完整性校验 → 持久化 → 发布；失败恢复内存，用户原文件保持不变。

完整性包括：版本、稳定 ID 唯一、操作 ID 幂等、同账本引用、两级分类、有效日期/金额、退款总额与原支出关系、预算及草稿。归档历史允许保留，不等于允许新交易使用。

导出备份包含当前可见账本、目录、交易、草稿、设置及校验清单，排除云绑定与其他账号隐藏缓存；恢复为本地数据，不自动恢复共享或回滚云端。清单检查数量和合计，并非数字签名或防恶意篡改认证。生成文件后需由用户在系统分享面板存到目标位置；生成时间不表示已完成外部存储。

恢复先读文件并隔离校验 → 展示账本/有效/删除记录数量 → 明确替换全部 → 保存替换前恢复点 → 原子落盘成功 → 更新界面。失败不切换内存。正常恢复可回到上次替换前；原文件损坏时先保存原始字节副本，不能把坏文件当成可用恢复点。读失败状态下备份和 CSV 导出禁用。

数据 → 本地恢复点：显示日期、大小及可用/不可读状态；可预览有效副本、导出或确认删除单个副本。不可读原文件副本只能导出/删除。取消删除不改变文件；删除最新恢复点先安全清除关联元数据，失败保留文件，不误删当前账本。没有自动保留期限或静默清理。分享面板关闭后只清理本次生成的临时目录，不清理外部导出或持久恢复点。

CSV 导出当前账本所有有效及回收站记录，状态列区分，保留稳定 ID/关系；逗号引号换行按 CSV 转义，公式起始字符加保护。CSV 是核对用途，不支持导入还原。

## 12. 可选 iCloud 与共同账本

账本名旁「同步与成员」逐账本开启，确认后上传这个账本的账户、分类、流水（含回收站及历史附加信息）、备注与预算；草稿、主题和其他账本不分享。同一系统 iCloud 账号设备发现已启用账本，不按账本名匹配。跨账号由拥有者点「邀请成员」，填写对方的 Apple 账户邮箱，选择一起记账或仅查看，再准备并复制私有链接；只有指定成员能加入，链接本身不会公开账本。成员打开链接、确认接受、下载并校验后切到共享账本。无需注册余记、好友表、组队码或自建服务器。

拥有者在系统面板管理只读/可编辑、移除成员和停止共享。只读可浏览统计与流水，统一业务写入拒绝改动；可编辑成员可修改共同账本，不提供“只改自己的账”权限。撤权无法收回已经导出或截图的数据，离线设备需联网得知。启动确认账号前隐藏云缓存；确认仍是同一账号后恢复上次选中的云账本，等待期间用户主动选择本地账本则尊重该选择。账号变更隐藏旧缓存，不把旧账号待传内容上传到新账号；纯本地账本始终可用。

记账先保存在本机；打开/返回前台/保存后尝试同步，设置页可立即同步或暂停自动同步。暂停不是退组，手动同步仍可用。状态区分待同步、已同步、暂停、连接错误及冲突，首页与设置共用同一文案。重复提交或丢失确认不新增重复交易；不能安全合并的两版保留，确认处理前另存未同步本地副本。成员退出先落盘独立副本，失败保留共享及输入，成功后回副本继续记账。

不以模拟自测代替真实 iCloud 通过。配置、真实双账号/生产验收及首版逐账本资产传输限制详见 [交付记录](icloud-delivery-2026-10-08/README.md)。

同设备换账号而仍参加同一本共享账本时，两个账号分别保留缓存和未同步修改；只捕获当前账号的可见数据。临时不可用保留已确认缓存并暂停云请求。初次开启需联网检查同源云身份；备份恢复后云端已有同源账本时先确认另建独立 iCloud 副本，原本地和原共同账本保留。

## 13. 自愿支持开发者

手动入口固定为我的 → 页面顶部独立入口「好用，请开发者喝杯☕吧」，置于账本管理之前，首次进入无需滚动即可看见并点击；无论是否支持过、是否达到邀请门槛，均可主动打开。进入支持页不预选金额，选择档位不会付款；主动点击支付才调用 Apple 购买。使用消耗型商品，不自动续费、不解锁额外权益。展示价格来自当前 App Store 地区的 Apple `displayPrice`，本地测试金额不是正式定价。监听地区变化，并在页面回到前台与付款前重新获取商品；价格、币种或地区与用户选择时不一致则先更新展示，要求再次主动确认，不按旧价格继续购买。系统购买期间地区变化由 StoreKit 取消并返回新价格，不能直接转换美元数值或硬编码人民币。打赏不会自动新增收入、支出或其他账本流水。

自动邀请仅统计此功能接入后的本机成功新建记录，跨所有账本累计：收入、支出、退款、转账各算一笔，以稳定记录 ID 去重。编辑、删除、撤销删除、导入、备份/恢复、云端拉取与历史库存均不增加计数；保存失败不计数。保留前 100 个不同 ID，不通过扫描现有账本推断使用量。

达到 100 后，先核对购买恢复状态和商品可用性；已支持者不再自动邀请。当前表单、键盘、错误提示或云加入邀请未退出时等待，不叠加弹层；不需要再创建第 101 笔才尝试展示。自动邀请标题「已经记下 100 笔」，说明「好用的话，请开发者喝杯咖啡吧。支持与否，都能继续好好记账。」；可点「请一杯咖啡」或「继续记账」，也可关闭。接受后先收起邀请，再打开同一个支持页。

邀请在展示前将 `consumedAt` 原子持久化；对保留本地文件的这次安装只邀请一次。关闭、重启、升级、恢复账本、切换账本均不重复；删除 App 清除本机文件后可重新计数。邀请和付款状态位于独立稳定目录，不进入账本备份、恢复、云同步或统计。邀请文件损坏/写失败保留原文件并停止自动邀请，不回滚已经保存的账单。账本提交与邀请日志是两个文件，进程在其间退出可能少计一笔，不损害账务数据。

付款为可重复的消耗型支持。每次打开都展示 Apple 最新金额、不预选档位；不因上次 pending/unknown 或旧日志拦住入口。仅当次核价及系统付款未返回时防止连点。取消安静回列表；pending/unknown 在列表内轻提示，可直接关闭，不提供历史状态检查或手动解除流程，不自动再次购买。Apple 验签且本机原子记录完成后，当前这次支持自动关闭弹窗并在原页显示「咖啡收到啦，谢谢你的支持。」；感谢不等待网络 finish。当前 pending 交易在同一操作上下文批准可反馈一次；用户重开新一轮后，历史确认只静默补收据，不关闭新页或改变新选择。已支持过可再次主动支持，重启不重放历史感谢。价格获取失败保留关闭/重试；真实记录损坏/不可写仍避免发起新付款。

消费 `DeveloperSupportKit` 的付款模型与 UI，并仅使用 `EngagementPromptKit` 的 UI，不接入使用时长计数、分析、后端、订阅或功能权益系统。正式商品注册、合同/税务/收款、真机 Sandbox、TestFlight 和审核均为独立验收项。2026-10-13 已创建三个消耗型商品草稿，回读付费协议有效、两份税表使用中、银行可用。App 免费、打赏 ¥6 / ¥18 / ¥30、首发中国大陆已由用户确认；2026-10-14 已回读新版真实 Sandbox 小小鼓励收据 ¥6/CNY，用户确认自动关闭和感谢体验正常；旧隔离收据继续保留，不要求重复付款。真实目录显示 ¥6 / ¥18 / ¥30。原始自动观察超时保留，人工体验与新交易证据独立记录；Production 与 TestFlight 仍另验。修正与证据见 [支付复审](support-payment-2026-10-14/README.md)。当前状态见 [发布准备](app-store-2026-10-13/README.md)，实现、本地 StoreKit 测试的实际范围与原生图见 [交付记录](developer-support-2026-10-08/README.md)。

## 2026-10-15：价格透明与测试环境边界

用户实际体验构建 9 后明确撤回“隐藏金额／去 App Store 确认”方案。支持页必须在主动购买前展示每档金额和币种，视觉与无障碍文案一致；默认不选，选中后按钮为“请一杯 · 金额”，仍在 App 内拉起 Apple 原生购买确认。不能通过隐藏金额、硬改符号或猜测汇率掩盖目录异常。

余记宿主统一显式使用 `SupportPricePresentation.localized`，不再按分发收据隐藏价格，移除旧 Debug 确认模式开关。金额来自 `Product.displayPrice`，不添加客户端价目表；当次目录复核、交易验签与收据持久化、重复支持和关闭重开保留。公共 SDK 的可选模式仍存在，但余记不调用。

恢复价格展示不代表美元问题修复。已安装构建 9 保留原行为，只作历史测试产物，不能用于送审；本地修改尚未分发。真实 TestFlight 商品报价与系统页/交易币种的一致性继续作为独立未关闭门槛，见 [价格方案撤回记录](release-validation-2026-10-15/price-transparency.md)。
