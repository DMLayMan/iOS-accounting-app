## 变更范围

- 版本比较按实体 ID 展示全部业务差异，包括较早流水、备注、金额、日期、分类、账户、删除、记账人和预算规则。相同字段与技术修订号省略；每批 30 项，可继续查看。只读比较不改合并算法，解决冲突仍先保存完整本地副本。
- 昵称编辑先提示受影响的只读账本；保存留在页面，显示本机待同步、共享延迟或同步完成。再次点“完成”返回；网络请求不阻塞退出，不扩大成员权限。
- 统计明细标题保留当前记账人及清除入口，姓名与顶部使用同一生成逻辑；取消筛选仍统一联动汇总、图表与明细。
- 未设预算缩为单行入口；同环比无百分比时移除“暂不计算”大号卡片，保留实际原因和展开分析。记账月/年预算合并摘要，可展开；正常分类预算按需展开，超预算仍直接显示最多两项。
- 支持页保留 Apple `displayPrice` 和明确金额按钮，新增刷新价格入口。付款前额外比较数值金额与 storefront 国家；当次展示报价与验签交易分别保存于原本地支持记录，不能把目录自洽当作实际支付一致。

## 价格结论

本人本轮只读确认“媒体与购买项目”的国家/地区为中国大陆。不能再用“可能登录美区”解释当前现象，也没有修改购买账号、地区或固定价格。历史 TestFlight 的 USD 目录/CNY 交易不一致仍待新包真实核对；本轮代码增强核价与诊断，不宣称修复 Apple 目录服务。

报价是应用收到的目录数据，不是验签交易的一部分；`quotedOffer` 为兼容的可选本地字段。收据金额仍取 Apple 验签交易。缺少报价/金额的历史记录判定为“未知”，不自动判为一致，不将旧交易关联到新面板，不限制主动重复支持。

来源：[Apple displayPrice](https://developer.apple.com/documentation/storekit/product/displayprice)、[onStorefrontChange](https://developer.apple.com/documentation/storekit/product/purchaseoption/onstorefrontchange(shouldcontinuepurchase:))。Apple 开发者论坛存在 [TestFlight 目录与系统币种不一致的开发者报告](https://developer.apple.com/forums/thread/847397)，仅作诊断参考，尚非本 App 根因证明，也不是 Apple 已承诺修复。

## 本轮额外发现与修正

1. 昵称刷新在途时保存，强制同步请求被 busy 分支丢弃：新增失败用例后，改为完成当前请求后合并执行下一次同步，10 条昵称状态测试通过。
2. 输入结束重复写回相同昵称会清除保存反馈：只在值实际变化时重置编辑状态。原生保存、冷启动、流水归属、恢复默认姓名及只读大字模式复验通过。
3. 公共键盘完成栏的外层 frame 没有保证按钮实际点击区：把 44pt 区域放进按钮内容，增加明确标识；验证一次点击收起键盘后完成预算修改、清空、无效输入与账本隔离。
4. 冲突比较日期直接插值输出 Swift 结构名：统一年月日格式，交易标题、退款关联及预算生效日共用格式函数；断言同时覆盖较早流水和预算标题。
5. 原生测试通过但 SE 最大字号截图中预算金额被挤成多行：大字模式改为优先提醒一个异常周期，说明与金额分行；完整金额单行，展开仍可查看两个周期。追加金额实际渲染高度与展开测试，截图逐张回收，不能仅依赖测试绿灯。

源码已创建 App 草稿 PR #3。私有 SDK 的独立只读 CI 凭据经用户授权配置，提交 `909c1b7` 的远端 Core 与 iOS build 均通过，见 [CI 访问记录](ci-private-dependency.md)。SDK 自身计费限制仍独立记录。
