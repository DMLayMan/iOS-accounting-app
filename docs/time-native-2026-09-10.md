# 紧凑时间入口与底部中间记账

用户已同意竞品研究后的方向，并指定新增记账回到底部 Tab 中间、稍突出展示。本轮为原生 SwiftUI 实现；[原生截图入口](../evidence/time-native/index.html)。

## 用户现在怎么用

- 系统 Tab 按“账本、流水、记账、统计、我的”排列。中间绿色圆角底、白色加号是动作入口；打开记账时不切换所选 Tab，保存或取消回到发起页，也保留该页的导航位置。
- 移除旧的右下悬浮加号、整段额外滚动留白。系统 Tab 仍可见的页面均能打开记账，录入 sheet 覆盖 Tab。没有重新绘制整条系统导航栏。
- 流水和统计在标题下同位置显示当前年月，配一个轻量下拉提示。原来的主页面月/年分段、前后箭头、月份长条及常驻快捷筛选条收进共用时间面板。
- 点年月 → 点年份直接定位 → 点月份应用。普通字号用四列三行展示 12 个月，避免小屏第四行被 sheet 边缘裁掉；大字号改为两列并可滚动。选择年份后取消不会改页面日期。
- 月/年/自定/全部共用一处。月、年选中即应用；自定包含首尾日期，结束早于开始时禁用应用；“本月/本年”为跟随日期变化的快捷选择；显式选择的历史月/年保持固定。
- 两页共享当前期间。写入账单不会重置期间；切换账本成功后回本月，切换失败仍保留原期间。进入单笔返回保留本页筛选和日期。

## 统计口径与行为边界

没有改变原有收支、退款归属和同环比公式。两页共用时间选择状态，但保留明确的计算边界：

| 查看方式 | 流水 | 统计 |
| --- | --- | --- |
| 当前月/年 | 所选自然周期，允许检索未来日期记录 | 截至今天的已发生收支；显示实际首尾日期 |
| 历史月/年 | 完整周期 | 完整周期，沿用月同比/环比、年度同比 |
| 自定 | 包含首尾日，可跨年 | 所选范围截到今天；不强套自然月预算或同比 |
| 全部 | 全部有效记录 | 记账范围起点至今天；图表与下方明细联动 |
| 纯未来期间 | 可检索未来记录 | 显示“这段时间尚未发生”，不把它当零支出结论 |

月/年预算沿用已有规则；自定和全部不计算跨期预算余额，界面解释按月/年查看预算与同环比。未复制 Dime 的整图横划翻月，避免干扰现有饼图与明细操作。

## 实现位置

- `Sources/YujiCore/BrowsingPeriod.swift`：相对/固定周期、自然周期范围、统计截止日和日期标题。
- `ios-app/Yuji/AppState.swift`：共享期间、当前账本日期边界、成功切换账本后的重置。
- `ios-app/Yuji/Views/PeriodPicker.swift`：共用时间按钮和时间面板。
- `ios-app/Yuji/Views/FeedView.swift`、`StatsView.swift`：接入共享日期；保留列表筛选、同页分析及已有统计公式。
- `ios-app/Yuji/Views/RootView.swift`：系统 Tab 中间动作及选中态拦截；`LedgerHomeView.swift` 同步移除浮动按钮留白。
- `Tests/YujiCoreTests/BrowsingPeriodTests.swift`、`ios-app/YujiTests/AppStateTests.swift`：日历边界、未来记录边界、期间保留和切账本失败回滚。
- `ios-app/YujiUITests/TimeNavigationUITests.swift`：日期与中间记账完整路径；原有相关 UI 用例已改为新的控件入口。

## 视觉复核与问题修正

第一轮同时检查 iPhone 17 Pro 和 iPhone SE 3 的普通、深色及最大辅助字号截图：

1. 中间加号视觉略突出，原 Tab 仍保持选中；四个目的页打开/关闭均正常，没有空白 Tab 过渡。
2. 小屏三列月份网格的第四行被初始面板边缘遮挡。集中修正为普通字号四列三行；大字号仍两列，通过滚动可达。
3. 小屏最大字号的年份和“本月”挤在一起。年份入口在该状态显示四位年份；主页面月份简写为 `2026.09`，无障碍名称仍读完整年月。
4. 最大字号流水固定头部不再重复放大收支汇总，为记录留出空间；日期和笔数仍可见。
5. 纯未来范围的父容器无障碍标识覆盖了子按钮标识，导致自动化无法找到“回到本月”。标识改到说明文字，按钮保留独立标识；原始失败日志保留。

## 验收记录

核心与状态层：`swift test` 101 项全部通过，包含原有 500 条、57 个月的独立预期值校验和新增 5 项日期/状态测试。日志：[swift-test.log](../evidence/time-native/swift-test.log)。

原生构建、UI 路径及最终截图的实际结果见 [verification.json](../evidence/time-native/verification.json)。首轮 `pro-first` / `compact-first` 各有一项未来范围按钮标识失败，不能把首轮称为全通过；最终结果按后续独立批次记录。截图取自最终批次 xcresult 附件，保留来源映射。

最终 11 个设备用例全部通过：iPhone 17 Pro 为 4 条新动线及 2 条预算/流水旧动线回归；iPhone SE 3 为 4 条新动线及 1 条底部记账/最后流水可达回归。包括普通、深色和最大辅助字号。最终画廊含 42 张原生截图；浏览器验证默认三张图片加载及分组切换正常。最后一条流水可打开，返回后仍可从中间入口记账。

最终构建日志保留了 AppIntents 元数据提取跳过提示；本轮所选测试日志未再次出现之前的 Invalid frame dimension 提示，这不代表整个应用运行时已完成告警清零。

所有 UI 测试使用每条用例新建的 `YUJI_STRESS_SESSION` 隔离文件；未卸载应用，未写个人 `ledger.json`，也未覆盖用户此前使用的体验 session。现有脏工作区保留，未提交或推送。

## 剩余限制

- 运行环境为 iOS 26.5 Simulator，真机签名未配置；不等同真机验收，未覆盖 iOS 16–25 的实际设备外观。
- VoiceOver 标识/触控目标通过自动化检查；实际朗读、真实触觉和长时间使用舒适度尚未实测。
- 自定范围的首尾沿用系统 DatePicker，范围应用与两页结果联动已纳入 UI 用例；逐一遍历系统日期控件的所有输入方式不在本轮覆盖范围。
- iCloud、多人同步未在本轮实现。HTML 页面仅展示真实原生截图，不作为 App 的实现。
