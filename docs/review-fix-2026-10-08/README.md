## 架构与维护边界

保留 `YujiCore → AppState → LedgerRepository`。不引入后端、账号、第二套主题、页面专属统计公式或未经量化的数据库重写。

交易索引只缓存偏移，`LedgerData.didSet` 对嵌套修改同样使其失效；不保存第二份可写交易。渲染期间复用结果，避免跨上下文缓存过时。分类预算仍按退款发生日和原分类计算，父子额度独立、净额可负，不改变 schema。

恢复点属于本地文件能力，删除须用户确认；云或数据库仓储不能直接沿用路径假设。未来异步持久化必须有有序提交、版本保护和失败回滚，不能只把同步方法放入后台队列。

## 防回归规则

1. 当前业务指标必须约定截至日期；允许未来流水不代表当前余额包含未来。
2. 长文本约束容器并保留全名读取路径，不靠禁用长名称。
3. 主题穿过真实 sheet 根与 UIKit；实心按钮正确不等于系统导航正确。
4. 检查点比较当前输入与最后落盘输入；只比较初始表单会复活撤回的草稿。
5. 路径别名不可直接当文件身份；规范化每个枚举 URL，测试删除隔离。
6. 退款与多条预算用于挑战复杂度；先测量，再加有失效契约的索引。
7. 发布资源、签名安装、分发、审核与下载分别验证，不以 archive 成功代替上架。
8. 调试器会改变时序。诊断探针的键盘焦点失败单独记录，不算产品回归结果。
9. 表单焦点由一个宿主持有；可见性、完成与提交共用同一状态。全局键盘通知不能识别当前任务归属。
10. Xcode 会忽略拼错的测试筛选名。入口先核对源码中的目标/类/方法；按用例身份去重，不用重复执行数冒充覆盖数量。
11. AX 的焦点失败不直接等于产品输入失败。检查真实键盘字符归属与保存结果；控件保持稳定 44pt，失败时诊断点击和录屏，不只增加手势。本轮曾把元素级 typeText 错误误判为 C 端焦点故障，定向诊断后纠正。
