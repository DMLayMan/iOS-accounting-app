# 产品与体验：先把用户任务做顺

适用于个人工具的新应用、新能力和体验重做。以下是从余记迭代提炼的设计启发式，不是对所有 iOS 应用的统一布局要求。

## 1. 实用功能的取舍

先补齐四句话：谁，在什么情境下，要完成什么，怎样才算完成。随后区分三类价值：

| 类别 | 判断方式 | 例子 |
| --- | --- | --- |
| 高频核心任务 | 不做它，应用就失去日常使用理由 | 快速记账、添加待办、查看今天日程 |
| 低频但关键保障 | 次数少，失败代价却很高 | 数据恢复、导出、撤销误操作、权限拒绝后的继续使用 |
| 可选增强 | 对部分用户有价值，应按需出现 | 自定义主题、复杂预算、更多分析维度 |

优先比较“发生频率、每次阻力、失败后果、学习成本、长期维护成本”。不要用一个看似精确的总分让低频恢复功能输给装饰功能。没有观察数据时写明假设；不要凭空声称用户每天使用多少次。

每个新增功能回答：它减少哪个任务的时间或不确定性？最轻的方案是什么？会新增多少概念、入口、权限、持久化字段和维护责任？无法指出受益任务的功能先进入候选清单。

## 2. 先统一概念，再设计入口

为核心实体写出：名字、含义、归属数量、创建/编辑/删除、历史引用、查找方式。

- 余记的快捷标签和手输标签让用户困惑，后来确认一笔账只归属一个二级分类。快捷选择、全部查找、分类管理都应指向同一集合。
- 不要据此得出“所有应用都应取消标签”。待办里的项目归属与跨项目的场景标签可能彼此独立；日历归属和参与人也不是同一个概念。
- 备注是否可搜索是产品规则。余记明确选择记录用途；笔记 App 的正文搜索则可能就是核心能力。

先确定语义和基数，再确定数据库和 UI。已经有数据时，为合并、归档和迁移单独设计兼容策略；不能靠删除旧 UI 宣告历史数据已迁移。

## 3. 绘制最短有效动线

用“进入 → 识别当前上下文 → 必要输入 → 完成 → 返回”描述主路径，标出每一次决策、切页、键盘变化和重复输入。点击少不一定好：隐藏长按可能减少按钮，却增加学习成本。

首次进入页面按第一次价值选择，而不是按代码中的第一个 Tab：

- 记账可先理解账本与累计；待办可先看到今天；日程可先看到接下来安排。
- 空状态直接提供第一项有效动作和必要说明，不先要求用户填全分类、主题和高级设置。
- 需要权限时，在功能确实需要它的位置解释用途，拒绝后有可理解的替代路径。
- 后续启动是否恢复上次位置要明确；不能每次因保存把用户送回默认页。

高频新增入口在拇指容易触达且跨页可预期的位置。中间 Tab、工具栏、列表内新增、浮动按钮都可比较；选择依据是使用频率、导航占用、遮挡与平台体验。余记最终采用中间动作 Tab，不代表所有工具都需要五个 Tab 或中央加号。

## 4. 容器决策表

| 用户实际在做什么 | 优先方案 | 必须保留的上下文 |
| --- | --- | --- |
| 改筛选、排序、选中图表 | 原页面联动，必要时滚到结果区 | 当前期间、对象、条件、统计口径 |
| 临时创建/修改一个小对象 | 可展开的 sheet 或聚焦编辑页 | 原输入与来处；成功后应用新对象 |
| 浏览一个对象的完整内容 | 详情导航 | 返回时的筛选、选中与滚动位置 |
| 确认不可撤销操作 | 清楚描述范围的确认 | 被影响对象、后果与取消能力 |
| 查看低频高级选项 | 同页展开或二级设置 | 不打断日常主操作 |

sheet 高度由内容、键盘、屏幕和大字号决定；70% 只是候选初始高度。不要层层叠 sheet，把用户带离原问题。统计钻取的默认问题是“这个总数由什么构成”，将对应明细放在图表下面通常比另开面板更连贯；复杂独立对象详情仍可导航。

## 5. 所有输入页都要有退出语义

| 状态 | 需要明确的行为 |
| --- | --- |
| 新建且未输入 | 可直接退出；不创建无用草稿 |
| 新建已有内容 | 按产品约定留草稿或提示；不要声称保存了实际未保存的内容 |
| 编辑已有对象但未变更 | 直接退出；不要只因加载时间戳变化判定 dirty |
| 编辑后取消 | 明确继续编辑/放弃，保护原对象与其他草稿 |
| 保存失败 | 原输入还在，可重试；不能先关页面再提示失败 |
| 系统返回、下滑、切后台、重启 | 分别定义行为，不能只覆盖取消按钮 |

专用数字键盘与系统文本键盘应由一个明确的输入模式控制；焦点切到名称/备注时收起数字区。退出确认先处理键盘和背景可编辑性。按钮禁用时，金额越界等原因就近可见，不能把解释藏在被禁用按钮的点击回调里。

## 6. 高频目录：快捷使用与管理同时成立

- 常用选择就近展示；少量项不要硬铺满多行，列表阅读顺序与视觉位置相符。
- 超出首屏的内容有明确的浏览或查找路径。搜索命中后应定位、选中、返回原任务，不让用户再找一次。
- 就地新增只问必要信息，创建成功后立即可用。图标选择与文案在同一编辑任务内。
- 手动排序拥有稳定的意义。自动推荐可用近期/频次等本地数据，但应分区或固定到明确的推荐位；不要每次打开都悄悄重排用户目录。
- 无历史使用数据时回到可解释默认；过滤不可用/归档项。用户编辑习惯时，推荐不能对抗手动安排。
- 引用中的项优先归档或迁移引用；删除和改名对历史的影响要说明。拖动结束提交一次，取消和保存失败都可恢复。

## 7. 时间浏览有两个不同任务

“看相邻月”和“找几年前某个月”需要不同成本的路径。快速翻期不能替代直接定位；直接选日期也未必满足连续浏览。

设计时写清手势作用区域、方向、跨年行为、空期、未来期和显式替代入口。不要把“顶部时间控件内横划”实现成“整页横划”。手势可作为熟练使用的增强，不应成为唯一入口；提示应嵌入结构，不再堆一排说明和符号。

两个页面统一时列出完整契约：周期类型、当前选中、按钮、日期面板、取消/应用、状态持有者。只有颜色相同不算复用。也不要错误统一业务含义：流水可以显示未来记录，统计可只截至今天，但都需要说明实际日期。

## 8. 统计从问题到可核对的记录

分析链：范围与口径 → 总数 → 构成 → 排序/变化 → 选中子集 → 明细 → 单条纠错 → 返回重新计算。

每张图或结论都要能回答：

1. 数值是什么，正负怎样解释，包含和排除什么？
2. 分母是什么，点击筛选后是否改变？
3. 当前页面哪些元素联动，哪些基准刻意保持不变？
4. 用户如何回到全部、核对原始记录、修正错误？

对比还要定义基期、相同截止日、零/负基期、历史覆盖不足、闰日和未来期间。无法比较时提供绝对差或原因，避免生成误导百分比。退款、取消完成、撤回等“反向事件”是否回溯原期间，必须先有领域规则。

饼图用于适合的非负构成，不强塞负值。排序既是阅读工具也是进入对应明细的入口。健康规则和长排行默认适度收起，有明确“更多/收起”；不要让低优先级信息把记录推到很远。

## 9. 美感落实到可检查的细节

先消除重复概念、入口和说明，再调字号、间距与色彩。保持稳定对齐、有限层级、系统语义字号和留白节奏。金额、时间和名称使用真实长文本、零值、大值验证，不只看漂亮样例。

| 色彩角色 | 用途 | 避免 |
| --- | --- | --- |
| 主题强调色 | 操作与选中 | 换主题让收入突然像错误 |
| 状态/业务语义色 | 收支、错误、成功 | 只用红绿、不写类型或符号 |
| 图表序列色 | 区分类目 | 与当前选择/错误颜色混用而无图例 |
| 中性色/表面 | 正文、分隔、背景 | 所有卡片都有强底色和阴影 |

自定义主题要同步根页面、弹层、UIKit 桥接组件、浅深色、禁用与选中态。颜色数值对比检查不能替代实际半透明材料和系统控件观察。

情绪价值优先来自确定感：不用担心丢输入、保存有回响、误操作可撤销、再次打开能继续、没有无端责备。微动效解释位置变化和完成状态；触觉反馈应有辨识作用。避免频繁庆祝、强制动画等待和羞辱性的预算文案。涉及减少动态效果、触觉和 VoiceOver 时，按实际可测试能力记录结果。

## 10. 调研与方案收敛

只围绕当前不确定性找少量高度相关样本。记录应用、平台、来源日期/版本、进入路径、观察到的交互和未验证部分。官方截图证明外观，源码证明某个版本的实现；两者都不能冒充已经原生操作过。

借鉴用户任务的解决方式，不盲复制皮肤、品牌或未经许可的素材。原方向连续被否定后，先解释问题属于语义、层级、动线还是视觉，再选择一个有依据的方向。不要给每个反馈都叠加控件，最终把所有探索同时留在页面上。
