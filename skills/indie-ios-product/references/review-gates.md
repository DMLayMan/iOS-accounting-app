# Review 与验收：自己先发现问题

检查是为了关闭风险，不是生成“全部打勾”的表格。没有可运行版本时只做设计/源码审查，并写清哪些结论缺少原生证据。

## 1. 四个互不替代的判断

| 维度 | 要问的问题 | 证据 |
| --- | --- | --- |
| 实用性 | 核心任务值得做吗？高级能力是否挤占主任务？ | 任务定义、用户已确认取舍、观察或待验证假设 |
| 动线 | 用户能发现、完成、纠错并回到来处吗？ | 真实进入/退出/失败路径，必要时录屏 |
| 视觉 | 层级、对齐、密度、颜色、文字、系统呈现协调吗？ | 默认与边界状态的原生截图 + 人工审查理由 |
| 工程 | 数据正确、状态一致、可恢复、可扩展吗？ | 领域/存储/交互测试、代码边界、实际运行记录 |

任何一项的高分不能抵消数据丢失或主操作不可达。不用自行打出的“9.5 分”代替缺陷、修复和可核查证据。

## 2. UI 批次检查

围绕本次改动选择实际相关状态，默认把普通屏、小屏、浅深色和大字号放在一次集中检查中。完成一轮问题收集后一起修，再确认一次；如果还有明确的功能失败继续处理，纯审美偏好分歧回到设计依据而不是无限微调。

页面检查点：

- 首屏的主信息与主操作是否一眼可认；固定头部/底栏占用是否必要；没有意义重复的入口。
- 核心区域的触达和阅读顺序；横向内容有查找或浏览入口；长名/极值/空态不把必要动作挤走。
- 默认、选中、禁用、错误颜色和文字保持同一语义；主题切换覆盖弹层和原生桥接。
- 数字键盘、系统键盘、退出确认互斥；保存被禁用时原因可见。
- 返回保留正确上下文；筛选解除和排序变化可解释；新对象保存后可以马上使用。
- 深色材料没有透出干扰文本；最大字号可以滚动访问全部信息和动作，不用强行缩字掩盖问题。
- 手势有明确区域、可取消与非手势路径；减少动态效果和无障碍标签相符。实际 VoiceOver 听读与截图检查分开。

记录发现时写“触发 → 影响 → 证据 → 修复 → 复测”，例如“SE 最大字号时滑动起点落在固定时间栏，测试没滚动”；不要只写“体验还需优化”。

## 3. 场景矩阵

| 场景组 | 代表条件 | 主要证明方式 |
| --- | --- | --- |
| 第一次使用 | 无数据、默认定位、必要权限被拒绝 | 原生路径 |
| 高频输入 | 新建/编辑、快速连续操作、粘贴、输入切换 | 原生路径 + 领域边界 |
| 中断与失败 | 关闭、下滑、后台、重启、保存失败、重复提交 | 故障注入 + 回读 |
| 检索与分析 | 当前/历史/空期间、组合筛选、下钻、返回 | 独立期望值 + 原生联动 |
| 管理变更 | 新增、改名、重排、归档、删除、引用中的对象 | 领域完整性 + 关键原生路径 |
| 数据维护 | 备份、恢复、坏文件、版本、替换前副本失败 | 临时仓储 + 原字节/对象断言 |
| 适配 | 小屏、深色、大字、长文案、键盘、无障碍 | 原生视觉/交互，能力不足写未验证 |
| 发布目标 | 安装、升级、真实权限/触觉、分发状态 | 对应设备与平台的实际记录 |

不要构造全部条件的笛卡尔积。基础变化做轻量检查，关键关系与异常做确定性测试，共享组件更改覆盖其实际调用方，交付基线跑核心场景全量。

## 4. 数据夹具要能推翻错误实现

真实形态比纯随机数量重要。余记用跨五年的 500 条合成数据验证历史、空月、退款、转账、归档和比较边界；其他应用应改用相应领域的跨期、重复、取消和权限情境。

准备少量手工可算的例子，加确定性批量夹具和独立 oracle。不要让期望值调用被测试函数；也不要把实现公式原样抄一遍，就称独立验证。补充守恒与关系断言，例如分组加总等于总数、筛选明细与所选指标一致、撤销恢复原状态。

区分产品缺陷与测试缺陷：检查交互命中、固定时钟、初始状态和测试宿主隔离；修复旧定位后保留正确业务断言。基期为零/负、未覆盖完整周期、范围跨界等应有明确结论，不能只断言页面没崩溃。

## 5. 证据口径

| 已看到的事实 | 可以说 | 不能外推 |
| --- | --- | --- |
| demo 可交互 | 验证了某个信息结构/选择方式 | iOS 键盘、手势和数据已可用 |
| 测试源码存在 | 有覆盖意图 | 测试通过 |
| 单元/领域测试通过 | 这些输入和不变量通过 | 原生页面美观、用户使用更快 |
| 原生模拟器通过 | 指定系统、设备配置、路径通过 | 真机、所有系统版本、触觉和功耗通过 |
| 未签名 Release 构建通过 | 设备目标可构建 | 已安装、已上架 |
| CI 绿色 | 对应提交的流水线通过 | 已合并或发布 |
| 设置写入成功 | 本地偏好已保存 | 云端同步已连通 |

全量后针对性复测可以合并，但按场景 ID 取最新结果并注明批次/产物，不把重复测试相加成覆盖数。不掩盖早期失败；驱动脚本、测试框架和业务断言分别记录，不能用其中一个成功替代其他状态。

## 6. 文档能否复刻

给不了作者现场解释，另一位实现者仍应知道：首次进入哪个页面、每页顺序、主要组件、点击/手势结果、状态归属、键盘与退出、空/错/大字/深色、指标口径和恢复语义。

当前 PRD 写规则，页面规范写布局与状态，架构写所有权与边界，验收记录写事实，图集写来源。一个主题只维护一个权威位置，其余链接过去。旧方案标“历史/已替代”，不与当前规范混放。生产数据、密钥、数 GB 构建产物不进入可移植示例。

## 7. 停止与交付

当前范围的核心任务可完成；数据/主操作风险已关闭；视觉发现已处理；需要的检查通过；文档对应实现；剩余限制明确，才交付。没有人类长期使用数据时，仍应写“完成原生走查”，而不是“达到极致体验”。

依据当前授权提交、推送、创建 PR 或发布。完成外部动作后读回实际状态。新建 Skill、设计文档或本地构建本身不会扩大既有授权范围。
